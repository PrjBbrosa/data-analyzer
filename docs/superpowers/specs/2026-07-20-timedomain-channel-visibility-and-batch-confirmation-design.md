# TimeDomain 通道可见性与批量勾选确认设计

## 背景与目标

当前通道树的复选框同时表达三件事：通道是否属于当前 View、是否在
TimeDomain 中绘制、是否作为 FFT 等分析页面的输入。Ctrl/Shift 多选通道后，
点击任一选中行的复选框还会立即把所有选中行统一勾选或取消，操作结果不够显式。

本次改动将“加入 View”和“在 TimeDomain 显示”拆成两个独立状态：

- 复选框控制通道是否加入当前 View，并继续作为共享分析输入的来源。
- 眼睛控制已勾选通道是否在当前 TimeDomain View 中显示。
- 批量选择后的复选框点击必须先明确提示影响范围，用户确认后才一次性生效。

## 方案比较

### 方案 A：独立眼睛状态（采用）

在通道行增加窄的“显示”列。复选框仍代表加入 View，眼睛只代表 TimeDomain
可见性。两个状态含义清楚，也可以独立持久化到每个 View。

代价是 ViewState 需要增加一个字段，通道树需要增加眼睛的绘制和点击命中逻辑。

### 方案 B：复选框三态

用未选、已选但隐藏、已选且显示三个复选框状态承载全部语义。界面更紧凑，
但三态还会与文件/采样率父节点的汇总状态冲突，用户也难以从复选框外观判断
“部分选择”与“临时隐藏”的区别，因此不采用。

### 方案 C：右键菜单显示/隐藏

不增加列，只在通道右键菜单中提供显示和隐藏。实现表面上更轻，但状态不可见、
发现性差，无法满足用户希望直接看见眼睛状态的目标，因此不采用。

## 状态模型

每个 TimeDomain `ViewState` 保存：

- `checked`：已加入该 View 的 `(fid, channel)` 列表，保持现有语义。
- `hidden_channels`：已勾选但在该 TimeDomain View 中隐藏的通道列表。

使用隐藏集合而不是可见集合，保证旧项目缺少新字段时自然迁移为“所有已勾选通道
都显示”。始终维持 `hidden_channels ⊆ checked`：

- 新勾选通道时，从 `hidden_channels` 移除，默认立即显示。
- 取消勾选通道时，也从 `hidden_channels` 移除。
- 点击睁眼时从 `hidden_channels` 移除；点击闭眼时加入。
- 删除文件或通道时清理对应隐藏状态。

该状态按 TimeDomain View 保存。分屏时主、对比 View 各自拥有可见性；切换焦点后
通道树投影当前焦点 View 的勾选和眼睛状态。眼睛不改变 FFT、FFT-vs-Time、Order
等页面读取的已勾选输入。

## 通道树交互

### 单通道

- 未勾选通道的显示单元格为空，不展示可点击眼睛。
- 勾选后显示睁眼图标，通道加入当前 View 并显示。
- 点击睁眼变为闭眼，只隐藏该通道的 TimeDomain 曲线及坐标轴。
- 点击闭眼恢复显示，不改变复选框状态。
- 眼睛点击只影响被点击行；即使当前有多行高亮选择，也不做隐式批量传播。
- 眼睛列仅在 TimeDomain 页面显示；进入其他分析页面时隐藏该列，避免把
  “时域显示”误解为全局输入开关。

图标必须有工具提示，睁眼为“点击隐藏此通道（仅影响时域图）”，闭眼为
“点击显示此通道（仅影响时域图）”。不能只靠颜色区分状态。

### 绘图表现

- 叠加模式：隐藏整个通道显示单元，包括原始曲线、滤波伴随曲线和该通道独占的
  Y 轴；共享轴组按仍可见的成员绘制。
- 分屏模式：隐藏后收起该通道整行子图，其余子图自动补位，不保留空坐标轴。
- 若被隐藏通道是首选叠加左轴，保留首选配置但临时选择第一个可见通道承载左轴；
  重新显示后恢复首选通道。
- 重新显示通道时优先恢复该 View 已保存的 Y 范围；没有保存范围的新通道按当前
  可见 X 窗口做一次 Y 自适应。不能覆盖其他通道已恢复的 Y 范围。
- 眼睛隐藏的是通道整体。全局“显示原始/显示滤波后”开关仍在通道显示后决定其
  内部哪类曲线可见。

眼睛只改变 TimeDomain 绘图呈现，不改变勾选派生的统计值或其他分析输入。状态栏
同时显示“已勾选 N，显示 M”，使两种数量的区别可见。

## 批量勾选确认

触发条件：Ctrl/Shift 高亮选择至少两条通道行，并点击其中一条选中行的复选框。
目标状态仍由被点击行决定，但任何状态修改都必须推迟到确认之后。

### 批量勾选

提示：

> 当前选中了 N 个通道，是否将它们全部勾选并显示？

按钮：

- `全部勾选并显示`
- `取消操作`

确认后，所有选中通道设为已勾选，并全部从 `hidden_channels` 移除。

### 批量取消

提示：

> 当前选中了 N 个通道，是否将它们全部取消勾选并从当前视图移除？

按钮：

- `全部取消勾选`
- `取消操作`

确认后，所有选中通道取消勾选，并清理其隐藏状态。

提示文案使用“当前选中的通道”描述高亮行，不使用容易与复选框状态混淆的
“已勾选的通道”。默认焦点放在 `取消操作`。取消或关闭对话框必须保持所有通道
原状态且不触发重绘；确认后原子更新全部行，只发出一次状态变化信号并只重绘一次。

单通道复选框点击不弹窗。文件、源和采样率父节点的批量勾选继续保留现有大通道数
性能警告，本次不把眼睛扩展到父节点，也不新增眼睛批量操作。

## 数据流与边界

```text
通道树复选框 ──► checked ──────────────► View 成员 / 分析输入
                         │
通道树眼睛 ────► hidden_channels         │
                         │               │
                         └──── 差集 ─────┴──► TimeDomain 可绘制通道
                                               │
                                               ├─ 叠加：曲线 + Y 轴
                                               └─ 分屏：紧凑子图行
```

View 捕获时同时读取 `checked` 和 `hidden_channels`；View 应用时先恢复两者，再执行
一次绘图。分屏焦点切换只投影状态，不应修改未聚焦 View。搜索和“已选”筛选仍按
复选框判断，不因眼睛关闭而隐藏通道行，否则用户会失去重新显示的入口。

## 异常与空状态

- 所有已勾选通道都闭眼时允许图面为空，但通道仍属于 View。图面应给出
  “已选择 N 个通道，当前均已隐藏”的非阻塞提示。
- 隐藏状态引用已不存在的文件或通道时静默丢弃，不阻止项目打开。
- 批量确认对话框打开期间若选择发生变化，确认动作使用弹窗前快照的通道集合；
  已被删除的通道跳过，剩余通道仍只触发一次更新。
- 闭眼操作不进入现有“大量通道叠加风险”确认。睁眼导致叠加风险升级时，先沿用
  当前 TimeDomain 风险提示；用户取消后保持闭眼状态且不重绘。

## 测试与验收

### 通道树

- 未勾选无眼睛；勾选后默认睁眼；闭眼不取消勾选；取消后清除隐藏状态。
- 多选复选框点击在确认前不修改任何行；取消无信号；确认统一状态且只发一次信号。
- 批量勾选会把已勾选但闭眼的成员恢复显示。
- 眼睛点击不传播到其他高亮行；搜索和“已选”筛选仍能找到闭眼通道。

### View 与持久化

- 旧 View/project 缺少 `hidden_channels` 时所有已勾选通道默认显示。
- View 切换、复制、项目保存/恢复能够保留各自隐藏集合。
- 分屏主/对比 View 的眼睛状态相互独立，焦点切换后通道树显示对应状态。

### TimeDomain 画布

- 叠加隐藏后曲线、滤波伴随线和独占 Y 轴一起消失，共享 X 范围保持不变。
- 分屏隐藏后整行收起，隐藏/恢复不会重新引入密集子图的空白间距。
- 隐藏首选左轴时使用临时可见左轴，恢复后回到首选通道。
- 重新显示有保存 Y 范围的通道时恢复该范围；新通道只按可见 X 做一次 Y 自适应。
- 所有通道闭眼时显示空状态，再睁眼可恢复，无崩溃或默认范围污染。

至少运行通道树、View 持久化、分屏路由、TimeDomain 画布和叠加网格相关 UI 测试，
并用真实渲染截图检查眼睛命中区、两种图标状态和分屏收起后的间距。
