# 标注编辑器：工具栏布局 + 手柄命中宽容度打磨设计

日期：2026-05-31
分支：`plan/pyqtgraph-timedomain-migration`
目标文件：`mf4_analyzer/ui/markup/editor.py`、`tests/ui/test_markup_editor.py`

## 用户反馈

本轮基于已落地的截图标注编辑器继续打磨，不新增标注工具。用户确认基础方向后提出 5 条具体修正：

1. 左侧关闭只保留一个红色 X 图标，单独左对齐。
2. 每个图标按钮使用矩形工具按钮，整体工具区居中。
3. 撤销/重做改成图标。
4. 保存和完成复制靠右对齐。
5. 二次移动/修改元素的宽容度太小。比如拖线段两端必须非常精准，否则就变成整体拖动；同类问题存在于所有元素。

## 当前实现证据

- `_build_toolbar()` 当前仍是单条 `QHBoxLayout` 顺序堆叠：关闭、样式、工具、撤销、重做、保存、完成复制。关闭/撤销/重做/保存仍是文字 `QPushButton`。
- `mousePressEvent()` 的交互优先级是先 `handle_at(point)`，再 `markup_item_at(point)`。这个顺序正确，但 `handle_at()` 只检查 8x8 手柄外扩 2 个 scene unit，实际热区太小。
- `markup_item_at()` 已有屏幕像素归一的模糊命中；手柄命中还没有同样归一，所以缩放下手感不稳定。

## 设计

### A. 工具栏三段布局

把工具栏拆成 3 个命名容器：

- `markupToolbarLeftGroup`：只放关闭按钮，左对齐。
- `markupToolbarCenterGroup`：放样式按钮、8 个工具按钮、撤销、重做，整体居中。
- `markupToolbarRightGroup`：放保存、完成复制，右对齐。

外层使用三列布局，左右列拉伸、中心列按内容宽度居中。这样右侧按钮宽度变化时，中间工具区不会跟着偏移。

### B. 图标按钮统一为矩形工具键

关闭、样式、工具、撤销、重做都使用 `QToolButton`：

- 固定尺寸约 32x32 或 34x32。
- `border-radius` 控制在 4px，视觉上是矩形工具键。
- 图标按钮不显示文字，语义通过 tooltip。
- 关闭按钮用红色 X 图标和轻微红色 hover/边框，保持独立左对齐。
- 保存/完成复制仍用文字按钮，其中完成复制保持蓝色主按钮。

### C. 手柄“视觉小，热区大”

保持当前 8x8 可见手柄，不把 UI 做笨重；只扩大不可见命中热区。

新增 `_HANDLE_HIT_SCREEN_PX = 14.0`。`handle_at(point)` 将该屏幕像素容差按 `self._zoom` 换算到 scene 坐标：

```python
tol = _HANDLE_HIT_SCREEN_PX / max(self._zoom, 0.1)
```

热区以手柄中心为基准，不再在可见 8x8 手柄外无限扩张，避免小矩形中心被边手柄抢走。手柄热区优先级不变：只要点在热区内，就拖手柄；不在热区但命中元素体，才整体移动。

覆盖对象：

- 线段/箭头端点 `p1/p2`
- 矩形角点和边
- 文字、画笔路径、序号的 `scale` 手柄
- crop handles

### D. Hover 与按下逻辑一致

`_cursor_for(point)` 继续复用 `handle_at(point)`。扩大热区后，用户在按下前就能通过光标判断接下来是“拖端点/缩放”还是“整体移动”。

## 范围外

- 不新增工具。
- 不改变已选元素的 undo/redo 命令结构。
- 不改变复制发布链路、缩略图、保存/完成复制行为。
- 不把手柄视觉尺寸变大；只扩大热区。

## 验收标准

- 工具栏左侧只有红色 X 图标关闭按钮；中间样式/工具/撤销/重做整体居中；保存/完成复制靠右。
- 撤销/重做为图标按钮，点击行为仍可撤销/重做。
- 在靠近线段端点、矩形角点、文字/path/number 缩放点的位置拖动时，优先调整手柄目标，不误触整体移动。
- hover 在扩大后的手柄热区内显示对应 resize 光标。
- `tests/ui/test_markup_editor.py` 离屏全绿，并做一次真实 Qt 平台 smoke。
