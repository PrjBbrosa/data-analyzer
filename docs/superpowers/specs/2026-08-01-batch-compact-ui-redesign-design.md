## 0. 本轮边界

本节记录 2026-08-01 最初的文档冻结边界；用户随后明确授权在
`codex/batch-compact-ui-redesign` 上执行。实际视觉补救、测试与离屏证据以 2026-08-02
superseding plan 为准，不能再把本段理解为当前“只写文档”的限制。

后续实施时：

- HTML 是批处理对话框的**最终视觉与可见操作基准**；组件层级、信息密度、文案、默认
  状态和显隐关系必须与它对标。
- 当前 Python/Qt、recipe、validation、runner 和 manifest 是**逻辑事实来源**。HTML 中的
  模拟数据和 JavaScript 只说明目标交互，不得被当成生产算法。
- 允许因 Qt 字体度量、原生滚动条、焦点框、可访问性和真实方法参数数量做小幅微调，
  但不得借“微调”改变三栏层级、删除已确认操作、恢复已删除的高级设置，或改变本 Spec
  的参数语义。任何偏差必须记录在最终离屏证据中。
- 本 Spec 不替代独立的
  `docs/superpowers/specs/2026-08-01-batch-qt-render-migration-design.md`。后者负责 PNG
  渲染内核；本 Spec 负责批处理配置 UI。后者测试工具仍可显式请求 CSV，交互式批处理
  UI 则固定生成 XLSX，不构成后端格式删除。

## 2. 目标布局与尺寸契约

### 2.1 窗口骨架

目标窗口以 HTML 的 1440×900 画布为主参考，并必须在 1080×760 的现有支持尺寸下可用：

```text
┌──────────────────────── 工具栏 50 px ────────────────────────┐
├────────────────────── 流水线摘要 62 px ──────────────────────┤
│ INPUT 29%             │ ANALYSIS 39%        │ OUTPUT 32%      │
│ 独立纵向滚动           │ 独立纵向滚动          │ 独立纵向滚动      │
├──────────────────────── 状态栏 54 px ─────────────────────────┤
└───────────────────────────────────────────────────────────────┘
```

- 默认最大内容尺寸对标 1440×900，最小支持高度 700 px。
- 三栏使用 29:39:32 stretch，不再等宽。
- 工具栏、流水线和状态栏固定在滚动区域之外；只有三个内容栏独立滚动。
- 常规输入控件高度 36 px；圆角、边框、色彩、留白和 active/disabled 状态对标 HTML。
- 1080×760 下可收紧内容边距与卡片间距，隐藏预设副说明和分组说明文字，但不能隐藏
  主操作、当前状态、错误或字段标签。
- 禁止为“塞得下”而缩小到不可读字号；必要时滚动，不横向压扁字段。

### 2.2 顶部工具栏与流水线

工具栏固定为：

1. `从当前单次同步`
2. `导入方案…`
3. `导出方案…`

流水线三段只显示可快速核对的事实：

- INPUT：文件数、已选信号数；
- ANALYSIS：方法 + 分组或预设状态；
- OUTPUT：当前启用的产物，例如 `XLSX + PNG`。

流水线不是可编辑表单，不重复展示长说明或路径。

## 3. Input 栏

### 3.1 文件摘要与管理器

主界面文件块最多占一行摘要：文件数、已加载/异常状态和 `管理文件` 按钮。点击后打开
模态文件管理器，复用现有 `FileListWidget` 的添加、移除、探测和错误展示能力。

约束：

- 打开管理器不得重新解析已经探测完成的数据源；管理器与主界面共享同一模型/状态。
- 关闭管理器后立即刷新文件数、共同信号宇宙、异常数、运行可用性和流水线摘要。
- 文件为空、探测失败、选中信号在部分源缺失等错误仍需可见，不能因紧凑化而丢失。
- 文件管理器的 OK/关闭只关闭管理器，不等于运行；修改实时写回当前 BatchSheet。

### 3.2 数据源与信号的区别

UI 使用以下稳定术语：

- **数据源（F）**：一个文件或容器中的一个逻辑 source，例如 `F1`、`F2`；
- **信号（S）**：跨数据源选择的通道名，例如 `S1=Torque`、`S2=Speed`。

目标策略与目标信号仍是两个控件：前者决定选哪些源，后者决定每个源上分析哪些通道。
不得把“数据源”和“信号”合并成一个选择器。

### 3.3 其他输入项

- 保留目标策略、目标信号和现有方法需要的 RPM/滤波输入。
- 删除 Input 区的 `时间范围` 控件及其空文本校验入口。
- 时域滤波保持紧凑单行/展开式现有语义；禁用时不占用大块空白。

## 4. Analysis 栏

### 4.1 方法切换

固定四个方法：`时域 / FFT / FFT vs Time / 阶次`。方法按钮驱动参数表、预设区、源数据
区间、坐标语义、dB 显隐和流水线摘要，所有派生状态必须由同一方法状态更新，禁止各面板
各自猜测。

### 4.2 时域图片分组波形卡

三张卡片是互斥选择，卡片内必须画可辨识的微型波形而非抽象斜线：

| UI 选择 | 内部值 | 波形图示 | 产物语义 |
|---|---|---|---|
| 每项单独 | `render_group_by=none` | 多个小坐标框，每框一条 `F×S` 波形 | 每个数据源×信号一张图；`4×3=12 张` |
| 按数据源 | `render_group_by=source` | 一个坐标框内固定 `F1`，叠加多条 `S1/S2/S3` 波形 | 每个数据源一张图；`每文件 1 张，共 F 张` |
| 按信号 | `render_group_by=channel` | 一个坐标框内固定 `S1`，比较多条 `F1/F2/F3…` 波形 | 每个信号一张图；`每信号 1 张，共 S 张` |

- 可见文案使用“按信号”，内部继续使用既有 `channel` schema，避免 runner/schema 迁移。
- 每项单独时布局选择禁用；分组时允许 `叠加 / 子图`。
- 图中至少通过标签、颜色或线型让固定维度与变化维度一眼可辨；不得仅靠三张相似线条。
- 张数摘要来自真实文件/逻辑源/目标信号集合，不使用 HTML 示例常量。

### 4.3 单次分析预设同步

谱分析方法使用单次分析现有命名空间：

| 批处理方法 | 单次分析预设 kind |
|---|---|
| `fft` | `fft` |
| `fft_time` | `fft_time` |
| `order_time` | `order` |
| `time` | 无分析预设区 |

必须抽出一个共享的轻量预设槽仓库，由单次 `PresetBar` 和批处理 `AnalysisPanel` 同时
消费。仓库保持当前 QSettings key、内建回退、旧 flat-dict 兼容、重命名、清空和重置语义。
批处理不得实例化隐藏的单次分析面板，也不得复制 `频率/均衡/时间` 名称或数值字典。

同步要求：

- 打开/显示 BatchSheet、切换方法、点击 `从当前单次同步` 时刷新对应 kind 的四个槽；
- 单次分析在同一进程内保存、重命名、清空或重置槽时，已打开的 BatchSheet 实时刷新；
- 槽 1–3 使用内建回退或用户覆盖；槽 4 使用单次分析的自定义槽；空自定义槽保留
  `自定义` 外观，但不得伪造一份持久化参数；
- 批处理点击槽后只应用该槽拥有的参数 patch，不覆盖文件、信号、输出目录、导出勾选
  等非槽字段；
- 推荐状态与已应用状态分开，推荐徽标不得让槽看起来已经应用。

### 4.4 已应用/已修改状态机

状态至少包括：

```text
未应用 ──点击槽──> 已应用(slot, snapshot)
已应用 ──修改槽拥有的任一字段──> 已修改·未匹配预设
已修改 ──点击槽──> 已应用(新 slot, 新 snapshot)
```

规则：

- `snapshot` 是槽实际应用后的规范化参数 patch，不是按钮名。
- 应用过程使用 guard 阻止控件赋值信号误触发“已修改”。
- 用户修改任何由该槽拥有的字段，只要规范化值与 snapshot 不同，就清除所有 applied
  选中态，并显示 `已修改 · 未匹配预设`。
- 改回原值不自动重新选中；只有再次明确点击槽才恢复 applied 状态，避免猜测与误导。
- 方法切换不自动声称某槽已应用；切回时按当前编辑状态展示，除非用户再次点击。
- 文件、数据源、目标信号、输出目录、导出开关等不属于分析槽的字段不取消预设。

### 4.5 方法参数与源数据区间矩阵

| 方法 | 分析域 | `time_range` 的唯一 UI 来源 | 右侧坐标范围 | dB 参考 |
|---|---|---|---|---|
| 时域 | 可选时间片段 | 右侧 X 轴手动范围；自动=全时段 | X 同时控制裁剪与显示，Y 只控制显示 | 隐藏且不写 recipe |
| FFT | 可选时间片段的频谱 | Analysis 中 `源数据区间` | X=频率显示，Y=幅值显示 | 显示 |
| FFT vs Time | 全部有效时域 | 无；recipe 必须移除/忽略旧 `time_range` | X=时间显示、Y=频率显示、Z=色阶显示，不裁剪分析输入 | 显示 |
| 阶次 | 全部有效时域 | 无；recipe 必须移除/忽略旧 `time_range` | X=时间显示、Y=阶次显示、Z=色阶显示，不裁剪分析输入 | 显示 |

“全部有效时域”指完成既有有限值清理、采样/滤波等合法预处理后的完整数据，不允许再由
遗留 `time_range` 静默截短。当前 `batch_preprocess.preprocess_batch_signal()` 会对所有方法
统一应用 `time_range`，实施必须在 recipe/BatchSheet 规范化边界按上表消除错误字段，不能
只隐藏控件。

时域坐标 X 的手动范围进入分析参数和显示参数时必须只有一个权威值；禁止 InputPanel 和
OutputPanel 再各存一份。FFT 的源区间与频率 X 显示范围则必须是两个独立字段。

## 5. Output 栏

### 5.1 可见控件

仅保留：

- 输出目录 + `选择…`；
- `数据文件`、`图片` 两个复选框；
- 固定事实摘要：`XLSX · PNG 1920×1080 · 冲突自动编号`；
- 按方法变化的坐标范围卡；
- 非时域方法的 dB 参考。

两种产物都未勾选时，预检阻止运行并在状态栏显示明确原因。

### 5.2 固定输出契约

交互式 BatchSheet 构造的 `BatchOutput` 固定为：

```text
data_format     = xlsx
image_format    = png
image_size      = 1920x1080
image_width     = 1920
image_height    = 1080
conflict_policy = auto_number
write_manifest  = true
resume_policy   = none（普通运行）
```

不可见的 DPI、背景和线宽从 `BatchOutput`/渲染器的单一规范默认取值，UI 不维护第二份
常量，也不显示第二行杂乱摘要。

边界说明：

- 后端/CLI 仍可保留 CSV 和其他兼容输入；本次只收缩交互式 UI，不删除公共 schema。
- 导入旧方案时，BatchSheet 将旧格式/尺寸/冲突字段规范化为上述固定值，并只提示一次
  `已按当前固定导出规则转换`；不得显示已导入但实际不会执行的旧值。
- 导出新方案写出固定值，保证重开后 UI/runner 一致。
- XLSX 不得静默截断。单个逻辑数据产物超过 Excel 每 sheet 行上限时，按稳定顺序拆为
  `data_001`、`data_002`… 工作表，并保持列名；无法写完整时任务必须失败且保留原子写语义。
- `validate_outputs()` 继续是输出 schema 的唯一验证权威；UI 不复制另一套合法值判断。

### 5.3 删除的常驻 UI

以下内容不出现在目标对话框：格式下拉、图片尺寸下拉、自定义宽高、DPI、背景、线宽、
冲突策略、manifest 开关、运行恢复策略、恢复 manifest 选择、仅重试失败、输出预览长文案、
预计文件数/冲突数大段说明。

runner 的 manifest/resume/retry 后端能力可为 CLI 或未来独立入口保留，但本次 BatchSheet
不暴露恢复 section，也不把 manifest 路径写入可复用方案。普通运行始终使用
`resume_policy=none`。

## 6. 状态栏与运行生命周期

默认 UI 不实例化可见 `TaskListWidget`。底部 54 px 状态栏包含：

- 左侧状态图标/文本；
- 紧凑任务事实，例如 `12 个任务 · 预计 24 个输出`；
- 中部进度条；
- `取消` 与 `运行`。

状态机：

| 状态 | 文案/进度 | 运行按钮 | 取消按钮 |
|---|---|---|---|
| idle-valid | 就绪 + 任务/输出摘要，0% | 可用 | 关闭对话框 |
| idle-invalid | 第一条阻塞原因 | 禁用 | 关闭对话框 |
| running | 当前序号/总数 + 简短阶段，确定进度 | 禁用 | 请求取消 |
| cancelling | 正在取消…，保留最后进度 | 禁用 | 禁用 |
| completed | 完成/失败/跳过计数，100% | 可再次运行 | 关闭 |
| failed/blocked | 一行错误摘要；详细信息在日志/manifest | 配置有效时可重试新运行 | 关闭 |

runner 的 `BatchProgressEvent`、`BatchRunResult`、取消 token 和线程生命周期继续是唯一事实
来源；状态栏只是投影。线程结束前不得解锁编辑或允许再次运行。详细逐任务结果继续写
manifest/日志，完成后可通过现有通知或打开输出目录访问，不在对话框底部复制一套列表。

## 7. 方案导入导出与“从当前单次同步”

### 7.1 从当前单次同步

同步必须走现有单次分析状态采集/`AnalysisPreset.from_current_single` 边界，包含当前方法、
源/信号、分析参数、滤波、RPM、坐标和 dB（适用时）。随后：

- 按本 Spec 规范化方法字段：时域去 dB；FFT vs Time/阶次去 `time_range`；
- 输出固定为 §5.2；
- 刷新共享预设槽名称/参数；
- 仅当参数确实来自一次显式槽应用时显示 applied；不能根据相同按钮名猜测。

### 7.2 方案导入导出

- 现有字段兼容读取，但方法不兼容字段由 `normalize_batch_params()` 清理。
- 旧 Input `time_range`：FFT 迁移到源数据区间；时域迁移到坐标 X；FFT vs Time/阶次
  丢弃并提示一次。
- 时域旧 dB 字段丢弃，不回写。
- 旧高级 output 字段按 §5.2 规范化。
- runtime-only 的文件选择、恢复 manifest、retry scope 不进入可复用 preset。

## 8. 实施不变量

- `BatchRunner` 保持 GUI-free，`batch.py` 顶层不得引入 PyQt。
- 分组 UI 继续产出现有 `render_group_by` / `render_layout` schema，runner 分组算法不复制。
- 坐标、dB、filter、RPM 和 recipe 合并只保留一个规范化快照；应用 preset 时的 signal
  guard 不得吞掉最终一次 recompute。
- 预检和真实运行使用同一 `get_preset()` 结果；不得让流水线摘要显示 A、runner 执行 B。
- fixed output 仍经 `validate_outputs()`、冲突分配器、原子写和 manifest 记录。
- 不因删除可见 TaskList 而停止 progress 事件消费；状态栏必须处理全部终态。
- 不把 HTML 的示例文件名、数量、路径、参数或延时带入产品常量。

## 9. 验收标准

### 9.1 行为验收

- 文件主区紧凑，管理器完成增删/错误/信号宇宙同步。
- 三张波形卡在不读说明文字时也能区分 F 固定、S 固定和 F×S 单项；张数与真实范围一致。
- 单次分析重命名/保存/重置预设后，批处理名称和参数同步；不存在第二份硬编码名称。
- 应用预设后编辑其参数，所有 applied 选中立即清除，且不自动重选。
- 时域无 dB、无 Input 时间范围；时域手动 X 确实裁剪分析并控制显示。
- 只有 FFT 显示/执行源数据区间；FFT vs Time/阶次带旧区间导入后仍分析全有效时域。
- UI 无格式/尺寸/冲突/恢复 section，实际产物只按勾选生成 XLSX/PNG 1920×1080，并自动编号。
- 默认无任务明细区；运行、取消、完成、失败都能由状态栏准确表达。

### 9.2 几何与视觉验收

最终实施必须生成真实 Qt BatchSheet 离屏截图，至少覆盖 1080×760 和 1440×900。目标：

- 固定行高相对 HTML 误差 ≤4 px；三栏主要分割位置误差 ≤6 px（Qt 原生 scrollbar 占位
  可在报告中单独解释）；
- 主要按钮/输入高度、对齐、圆角和色彩层级一致；
- 1080×760 无横向截断、重叠、不可达控件或底部状态栏溢出；
- 1440×900 的空白密度、三栏比例和 HTML 同屏信息量一致；
- disabled、active、dirty、error、running 状态都能从截图辨认。

### 9.3 最终离屏截图矩阵（硬 Gate）

至少生成并检查：

1. 时域默认 + 每项单独；
2. 时域按数据源、按信号（各一张）；
3. 文件管理器打开；
4. FFT 槽 1 已应用；
5. FFT 参数修改后未匹配；
6. FFT 指定源数据区间；
7. FFT vs Time（无源区间）；
8. 阶次（无源区间）；
9. 时域坐标卡（无 dB）与谱方法坐标卡（有 dB）；
10. 仅 XLSX、仅 PNG、两者同时启用；
11. running / cancelling / completed / blocked；
12. 1080×760 与 1440×900 总览对标图。

离屏工具必须隔离 QSettings 与用户配置、固定字体/缩放、记录 commit SHA、Qt platform、
窗口尺寸和产物路径。执行者必须实际打开总览/contact sheet，逐项记录 PASS/FAIL；HTML
截图、widget 属性断言、pytest 摘要或其他 agent 的结论均不能替代最后一次真实 Qt 目视确认。

macOS 前台真机验收仍是独立证据；离屏 Gate 通过不能写成前台已验证。
