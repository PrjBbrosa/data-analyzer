# View 文件装载与通道配置设计

## 1. 背景

当前左侧导航包含两个不同作用域：

- 上方文件列表表示应用已经打开的全部文件。
- 下方通道树也始终列出全部已打开文件的全部通道。

`ViewState.checked` 只保存当前 TimeDomain View 勾选的通道。因此，新建 View
虽然没有勾选项，下方通道树仍然列出所有文件；文件较多时，用户需要在与当前 View
无关的大量候选中反复查找通道。

用户还需要把一组常用通道名称保存为多个配置，并把配置一键应用到当前 View 内
不同文件的同名通道。加载配置必须与真正应用分开，避免浏览配置时立即改变勾选和
触发重绘。

本设计扩展
[TimeDomain 通道可见性与批量勾选确认设计](2026-07-20-timedomain-channel-visibility-and-batch-confirmation-design.md)。
原设计中的 `checked` 和 `hidden_channels` 语义继续有效；本设计在其上增加
View 级文件装载和可复用通道配置。

## 2. 目标

1. 明确区分“应用已打开文件”和“当前 View 已加入文件”。
2. 新建 TimeDomain View 时，下方通道树为空。
3. 支持把上方文件拖入当前聚焦 View。
4. 支持用户决定新加载文件是否自动加入当前 View。
5. 支持保存多个按通道名称定义的配置。
6. 使用下拉框加载待应用配置；加载不修改当前勾选。
7. 应用配置时，在当前 View 内按同名通道完全替换勾选集合。
8. 覆盖已有配置、移除已选文件和大量通道应用均具有明确确认边界。
9. 保持 View 切换、分屏聚焦、项目保存/恢复和旧项目迁移可预测。

## 3. 非目标

- 配置不保存文件 ID、文件路径、通道颜色、眼睛状态、轴配置或坐标范围。
- 配置不自动打开文件，也不自动把全局文件加入 View。
- 配置不做模糊匹配、大小写折叠、别名推断或单位匹配。
- 本期不实现云同步、配置导入/导出或团队共享。
- 本期不改变 FFT、FFT-vs-Time 和 Order 自己的 Analysis View/Pane source
  持久化模型；配置入口和 View 文件装载首先作用于当前聚焦的 TimeDomain View。

## 4. 术语与状态层级

```text
应用已打开文件 files
        │
        ├── attached_file_ids ──► 当前 View 的通道候选
        │                              │
        │                              └── checked ──► View 成员 / 分析输入
        │                                                   │
        │                         hidden_channels ───────────┤
        │                                                   │
        └───────────────────────────────────────────────────┴─► TimeDomain 可见通道
```

- **全局文件**：`MainWindow.files` 和上方 `FileNavigator` 文件列表中的文件。
- **已加入文件**：当前 View 的 `attached_file_ids` 所引用、且仍存在于全局文件中的
  文件。
- **已勾选通道**：当前 View 的 `checked`，必须属于已加入文件。
- **待应用配置**：用户在下拉框中选中的命名配置；选择它不修改 `checked`。
- **当前 View**：TimeDomain 当前聚焦 View；分屏时由主栏/副栏焦点决定。

始终维持：

```text
checked.fid ⊆ attached_file_ids
hidden_channels ⊆ checked
```

## 5. 方案比较与选择

### 方案 A：顶部文字胶囊 + 底部双按钮

优点是“自动加入”含义直观、底部紧凑；缺点是文件标题栏横向空间有限，配置能力
扩展为多个命名配置后，双按钮入口不足以持续显示当前配置。

### 方案 B：文件策略说明条 + 模板工具栏

优点是初次使用容易理解；缺点是长期占用文件列表高度，窄侧栏中信息密度过高。

### 方案 C：顶部图标开关 + 底部配置行（采用）

文件标题栏使用带 tooltip 的自动加入图标。通道树底部使用一行固定控件：

```text
[ 保存 ] [ 选择配置… ▼ ] [ 应用 ]
```

该方案保持顶部紧凑，同时持续显示待应用配置，并将保存、选择和应用拆成独立动作。

## 6. View 状态模型

### 6.1 `ViewState.attached_file_ids`

`ViewState` 增加：

```python
attached_file_ids: list[str] = field(default_factory=list)
```

语义：

- 列表只保存当前 View 已加入的 fid。
- 顺序为文件加入该 View 的顺序，用于稳定投影通道树父节点。
- 新建 View 的默认值永远是空列表。
- 复制 View 时随其他 ViewState 字段一起复制。
- 删除全局文件时，从所有 View 的列表中清理对应 fid。

加入文件不会自动勾选通道。它只使该文件的通道成为当前 View 的候选。

### 6.2 状态清理

从 View 移除一个 fid 时，原子清理：

- `attached_file_ids` 中的 fid；
- `checked` 中属于该 fid 的键；
- `hidden_channels` 中属于该 fid 的键；
- 该 fid 对应的 View 颜色状态；
- 若 `overlay_primary` 指向该 fid，则清空首选左轴。

删除全局文件时，对每个 View 执行相同清理。剩余 View 的 X/Y 范围按现有
TimeDomain 状态保留规则处理。

### 6.3 通道树投影

上方文件列表继续由全局 `MainWindow.files` 驱动。下方 `MultiFileChannelWidget`
只投影当前 View 的 `attached_file_ids`：

- View 切换或分屏焦点切换时，先投影已加入文件，再恢复 `checked` 和
  `hidden_channels`。
- 未加入文件不得出现在搜索结果、“已选”过滤或父节点汇总中。
- View 捕获时同时保存 `attached_file_ids`、`checked` 和 `hidden_channels`。
- 切换投影不修改未聚焦 View。

## 7. 文件区域交互

### 7.1 自动加入开关

在“文件”标题、文件数量和 kebab 菜单附近增加 checkable 图标按钮：

- 开启：蓝色激活态；tooltip 为“新加载文件自动加入当前 View”。
- 关闭：灰色普通态；tooltip 为“新加载文件仅打开，不加入当前 View”。
- 偏好通过用户级 `QSettings` 持久化。
- 新安装默认开启，以保持当前“加载后立即可浏览通道”的行为。

开启后，新加载文件只加入加载完成时的当前聚焦 TimeDomain View，不加入其他 View。
关闭后，文件只出现在上方列表。

无论开关状态如何，`ViewManager.new_view()` 创建的新 View 都保持
`attached_file_ids == []`。自动加入只响应之后发生的新文件加载，不回填已经打开的
文件。

一次源文件加载可能生成多个 fid，例如 HDF/WWT/ZFD/MAT 的多个 raster/group。
自动加入以源文件加载事务为单位，把本次成功生成的全部 fid 一次加入当前 View，
只投影和重绘一次。

打开项目期间必须暂停自动加入。`open_project()` 通过 `_load_one()` 重新读取源文件时，
不得污染临时默认 View；项目中持久化的 View 状态在 fid remap 后统一恢复。

### 7.2 从上方拖入当前 View

每个 `_FileRow` 提供拖动手柄。拖动使用应用内部 MIME payload，不复用外部文件 URL
导入语义：

- 普通文件行携带一个 fid。
- 聚合源文件行携带该行全部 fid。
- 拖入下方通道区域使用 copy 语义；上方文件行不会移动或消失。
- 拖动进入时，通道区域显示“加入当前 View”高亮。
- 成功后提示“已加入主栏/副栏 · View 名称”。
- 已经全部加入时不修改状态，只提示“文件已在当前 View 中”。
- 部分 fid 已加入时，只追加缺少的 fid，并保持既有顺序。

外部操作系统文件拖放继续走现有 MainWindow 文件导入流程。文件导入完成后，再由
自动加入偏好决定是否加入当前 View。

### 7.3 空状态

当前 View 没有已加入文件时：

- 搜索和批量按钮保持不可操作；
- 通道树显示“当前 View 尚未加入文件”；
- 次级说明为“从上方拖入文件，或开启自动加入”；
- 不创建占位文件节点或虚假通道。

### 7.4 从当前 View 移除

文件/源父节点最后一列在 hover 时显示 `×`，tooltip 为“从当前 View 移除”。该列在
通道叶子上继续承载 TimeDomain 眼睛状态，因此不新增永久列宽。

- 节点没有已勾选通道时直接移除。
- 节点包含已勾选通道时提示：

  > 从当前 View 移除“Run_01”后，将取消 N 个通道。是否继续？

- 按钮为 `从当前 View 移除` 和 `取消`，默认焦点为 `取消`。
- 聚合源节点一次移除其全部 fid。
- 移除不关闭全局文件，不影响其他 View。

## 8. 通道配置模型与存储

### 8.1 配置内容

配置是用户级、跨项目复用的数据：

```text
schema_version
config_id
name
channel_names
created_at
updated_at
```

- `config_id` 是稳定标识，重命名不改变 ID。
- `name` 去除首尾空白后不能为空。
- 名称按 `casefold()` 判重，但保留用户输入的显示大小写。
- `channel_names` 来自当前 View 的 `checked`，按首次出现顺序去重。
- 配置只保存通道名称字符串；相同名称跨多个 fid 只保存一次。
- 配置采用带 `schema_version` 的 JSON，通过可注入的 `QSettings` store 持久化。

没有已勾选通道时禁用 `保存`，避免意外创建空配置。清空当前 View 已有“全不”入口，
不需要通过空配置间接完成。

### 8.2 保存新配置

点击 `保存` 打开轻量命名对话框：

- 显示“当前勾选 N 个通道”；
- 名称框默认使用当前待应用配置名；没有待应用配置时为空；
- 用户输入未占用名称时，创建新配置；
- 成功后将新配置设为下拉框的待应用配置；
- 提示“已保存配置‘名称’ · N 个通道”。

### 8.3 覆盖已有配置

保存对话框允许输入或选择任意已有配置名。命中已有名称时不立即写入，必须二次确认：

> 配置“动力分析”已存在<br>
> 原 N 个通道 → 新 M 个通道<br>
> 覆盖后无法从应用内撤销

按钮为：

- `覆盖配置`
- `取消`

默认焦点为 `取消`。取消或关闭对话框不写设置、不改变待应用配置、不触发重绘。
确认后只更新该配置的 `channel_names` 和 `updated_at`，保留 `config_id` 和
`created_at`，并提示“配置‘名称’已更新”。覆盖配置不会自动应用到当前 View。

### 8.4 配置下拉框

底部中间控件直接显示待应用配置：

- 无选择时显示“选择配置…”；
- 有选择时显示配置名，并在辅助信息中显示“N 个通道”；
- 选择下拉项只改变待应用 `config_id`，不得修改任何通道勾选或触发重绘；
- 配置较多时支持按名称搜索；
- 列表项显示配置名、通道数量和最近更新时间；
- 列表底部提供“管理配置…”，用于重命名和删除。

删除配置必须确认。删除当前待应用配置后，下拉框回到未选择状态，`应用`禁用。
重命名仍遵守名称判重规则。

待应用配置不写入 `.tlproj`，也不随 ViewState 持久化。它是用户当前会话中的 UI
选择，不是图表结果状态。

## 9. 完全替换应用语义

### 9.1 按钮可用条件

`应用`仅在以下条件同时成立时启用：

- 已选择一个仍存在的配置；
- 当前聚焦 View 至少有一个仍存在的 `attached_file_ids`。

### 9.2 匹配规则

应用前先做无副作用 preflight：

1. 读取配置的去重通道名称集合。
2. 只遍历当前 View 已加入且仍存在的 fid。
3. 对 `FileData.get_signal_channels()` 使用精确字符串相等匹配。
4. 同一名称在多个已加入文件中出现时，全部纳入结果。
5. 全局已打开但未加入当前 View 的文件不参与匹配。
6. 统计目标文件数、匹配通道键、缺失配置名和最终通道总数。

大小写不同、前后空白不同或显示标签相似均不视为同名。匹配使用原始 channel name，
不使用带文件前缀或截断后的 display label。

### 9.3 零匹配保护

如果最终匹配数为零：

- 不修改 `checked`、`hidden_channels` 或画布；
- 不发 `channels_changed`；
- 警告“配置‘名称’在当前 View 的已加入文件中没有匹配通道”；
- 提供缺失名称摘要，但不弹出阻塞式长列表。

零匹配保护高于“完全替换”，防止错误配置或错误 View 意外清空现有选择。

### 9.4 原子替换

存在至少一个匹配时：

```text
next_checked = 全部匹配到的 (fid, channel)
next_hidden  = old_hidden_channels ∩ next_checked
```

- `checked` 完全替换为 `next_checked`；不在配置结果中的旧勾选全部取消。
- 之前已勾选且隐藏、应用后仍存在的通道继续隐藏。
- 本次新匹配的通道默认显示。
- 不保存或应用颜色、眼睛、轴、X/Y 范围。
- 如果 `overlay_primary` 不在 `next_checked`，清空首选左轴；仍存在则保留。
- 整个替换只发一次状态变化信号并只触发一次 TimeDomain 重绘。

如果最终通道数触发现有大量通道性能风险，必须在写入前复用风险确认。用户取消后
保持所有状态不变。

### 9.5 结果反馈

完整匹配：

> 已应用“动力分析”：3 个文件，匹配 12 个通道

部分缺失：

> 已应用“动力分析”：3 个文件，匹配 11 个通道，缺失 1 个名称

缺失名称通过可展开详情或 tooltip 查看，状态栏/toast 不拼接不受限的长名称列表。

手动改变勾选后，如果当前勾选集合不再等于最近应用配置在当前 View 的解析结果，
配置区域显示“已修改”。该标记只是提示，不阻止保存、切换配置或再次应用。

## 10. 捕获、应用与项目持久化

### 10.1 View 切换顺序

`view_bridge.apply_controls_from_state()` 的逻辑顺序必须是：

1. 投影 `attached_file_ids`；
2. 恢复 `checked`；
3. 恢复 `hidden_channels` 和其他 View 控件；
4. 只执行一次绘图。

捕获顺序为先读取已加入文件，再读取已勾选/隐藏通道，确保保存的 `checked` 不会引用
未加入文件。

### 10.2 项目保存与 fid remap

`.tlproj` 的每个 TimeDomain View 保存 `attached_file_ids`。项目打开时：

- `project_io.remap_view_fids()` 同时 remap `attached_file_ids`、`checked`、颜色、
  `hidden_channels` 和 `overlay_primary` 中的 fid；
- 缺失文件对应的 attached/checked/hidden 引用静默丢弃；
- 保留剩余文件的相对加入顺序；
- 恢复完成后再投影活动 View，避免加载过程中重复重绘。

### 10.3 旧项目迁移

旧 `.tlproj` View 缺少 `attached_file_ids` 时，`open_project()` 在所有文件加载并建立
`fid_map` 后，将该 View 迁移为“所有成功恢复的文件均已加入”。这是对旧版通道树
始终列出全部文件行为的兼容。

新建 View 和全新项目不走该迁移，仍以空列表开始。必须区分：

- 字段缺失：旧项目，迁移为全部成功恢复文件；
- 字段存在且为 `[]`：用户明确保存的空 View，保持为空。

## 11. 异常与边界

- 拖动期间目标 View 被删除或焦点切换时，以 drop 时的当前聚焦 View 为目标；目标
  无效则取消并提示，不把文件加入其他 View。
- 文件加载部分成功时，只加入成功生成的 fid。
- 配置 store JSON 损坏时保留可解析条目，隔离损坏条目并提示一次；不得阻止应用启动。
- 配置引用已不存在的名称属于普通缺失，不修改配置内容。
- 覆盖确认打开期间勾选发生变化时，确认保存使用打开确认框前冻结的名称快照。
- 应用 preflight 后、提交前文件被关闭时，丢弃已不存在的键；若结果变为零则触发
  零匹配保护。
- 从 View 移除、配置覆盖、配置删除和风险确认的默认焦点均为取消。

## 12. 测试与验收

### 12.1 ViewState 与迁移

- 新 `ViewState` 的 `attached_file_ids == []`。
- `to_dict()` / `from_dict()` 保留加入顺序。
- 复制 View 保留已加入文件；新建 View 不继承。
- 旧项目字段缺失时附加所有成功恢复文件。
- 显式空列表项目恢复后仍为空。
- fid remap 同时覆盖 attached/checked/hidden/overlay primary。

### 12.2 文件导航与拖放

- 上方仍显示全部全局文件，下方只显示当前 View 已加入文件。
- 普通文件和聚合源 drag payload 分别携带一个/多个 fid。
- drop 只影响当前聚焦 View，重复 drop 幂等。
- 分屏主/副栏 attachment 相互独立，焦点切换投影正确。
- 自动加入开启/关闭分别只加入/不加入当前 View。
- 新建 View 在自动加入开启时仍为空。
- 项目 restore 期间 `_load_one()` 不触发自动加入。
- 移除含勾选通道的文件必须确认；取消无状态变化、无信号、无重绘。

### 12.3 配置存储

- 保存多个配置并按名称/ID读取。
- 名称 trim、空名称拒绝和 casefold 判重。
- 通道名称按首次出现去重。
- 覆盖保留 `config_id`/`created_at` 并更新内容/`updated_at`。
- 覆盖取消不写 QSettings。
- 删除当前待应用配置后清空下拉选择。
- 损坏配置条目被隔离，不影响其他条目。

### 12.4 应用语义

- 精确同名匹配覆盖当前 View 所有已加入文件。
- 大小写不同、显示标签相似和未加入文件不匹配。
- 应用完全替换旧 `checked`，不做追加。
- 仍匹配的隐藏通道保持隐藏；新匹配通道默认显示。
- 零匹配保持原状态且不发信号。
- 部分缺失应用匹配子集并给出计数。
- `overlay_primary` 在被替换掉时清理。
- 一次应用只发一个状态变化信号并只重绘一次。
- 大量通道风险确认取消后保持原状态。

### 12.5 视觉与回归

- 真实渲染截图检查顶部自动加入图标的开/关状态、tooltip 命中区、空状态、父节点
  hover 移除按钮和底部“保存/配置下拉/应用”在最小侧栏宽度下不截断。
- 运行 `tests/ui/test_file_navigator.py`、`tests/ui/test_view_state.py`、
  `tests/ui/test_view_switch_integration.py`、`tests/ui/test_project_session.py` 和相关
  TimeDomain/overlay UI 回归。
- 保持前置通道可见性设计中的眼睛、批量确认、Y-fit 和 X 范围保留测试通过。

## 13. 已确认决策

1. 自动加入只作用于当前 View。
