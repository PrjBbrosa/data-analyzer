## Residual risk and follow-up

- **Vector hardware + Windows workstation required to clear Tasks 4–6.**
  This is the explicit gate to leave PARTIAL and reach PASS. The
  runbook §Vector Access and §XCP CONNECT And SHORT_UPLOAD sections
  hold the verbatim commands to re-run.
- **Seed/Key handshake may be required by the target ECU before
  `SHORT_UPLOAD` succeeds.** The current XCP probe
  (`can_logger/p0/xcp_short_upload_probe.py`, per plan §Task 5) does
  NOT implement Seed/Key. If a real ECU returns a negative response
  immediately after `CONNECT`, treat this as a BLOCKED with a narrow
  next action — extend the probe to perform `GET_SEED` / `UNLOCK`
  before re-running `SHORT_UPLOAD`. Do not silently demote the gate
  to PASS without that extension.
- **`P0_A2L_PATH` is unset on this host.** The A2L gate is green in
  skip state; to actually exercise `pya2l.DB.import_a2l` against a
  real ECU file, the runbook §A2L Parse section documents the env-var
  invocation.
- **Production DAQ UI on real hardware** (cockpit Capture state wired
  to live Vector / XCP) MUST NOT begin until the P0 Final Verdict is
  **PASS** or a documented narrow PARTIAL whose blocker is named and
  bounded, per the program master plan §"Deferred Until P0 PASS
  (or documented narrow PARTIAL)". Scope was clarified on 2026-05-15
  (see `reports/2026-05-15-capture-priority-replay-findings.md`):
  the gate does **not** block the CLI recorder MVP backend (fake-bus
  path), cockpit UI scaffolding against mock data, or Modules A / B / C
  (offline preflight / manifest / regression / alias).
