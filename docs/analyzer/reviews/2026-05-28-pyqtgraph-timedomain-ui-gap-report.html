pyqtgraph TimeDomain — UI / 交互缺陷分析报告

分支 plan/pyqtgraph-timedomain-migration · 日期 2026-05-28 · 对比基准：matplotlib 原始渲染器 canvases.py::TimeDomainCanvas + 参考截图（图二）
方法：静态代码审查 + 两张运行截图比对（未启动实时 GUI）。每条缺陷均给出 文件:行号 根因。

结论速览：当前 pyqtgraph 画布完成了「能跑」的骨架，但与原始 matplotlib 设计相比存在 3 个功能性硬伤（P0） 和 5 个外观 / 交互一致性缺口（P1）。 其中最关键的是：整条 envelope→QPainterPath→QPixmap「重绘缓存」管线没有任何渲染消费方—— 缓存被计算却从不上屏，缩放时曲线不会重采样变清晰；同时单/双游标在实时 UI 中完全未接线。 所谓「~14x faster pan」有一部分来自「平移时其实没有重绘」。

缺陷清单（按严重度）

P0 功能 / 正确性硬伤 P1 与原始设计 / 参考图的一致性缺口 P2 次要打磨

#级别症状根因（文件:行）
1P0 缩放放大后曲线仍是「全程粗采样」，不会变清晰；平移其实没有重绘 重绘缓存无消费方：pg_canvases.py:1066 写 _curve_path_cache，但无 paintEvent/drawPixmap，setData 在平移路径被刻意禁用（:1072）；可见曲线始终是 _bind_channel 的全程 8000 点包络（:495）
2P0 单游标 / 双游标按钮点了没反应，画面上无游标竖线 _emit_single_cursor_html/_emit_dual_cursor_html（pg_canvases.py:1454/1477）从未被调用；main_window.py:348-349 只翻转状态位；无 InfiniteLine、无点击接线
3P0 缩放只能缩放最上方的图；各子图 X 轴范围不同步（图一第 2 图 2.5–8.5，其余 0–80） 滚轮缩放写死 _primary_xaxis_ax（pg_canvases.py:1412），忽略光标下的 ViewBox；工具栏 pan/zoom 只对主 ViewBox 设鼠标模式（chart_stack.py:417,441）；未用共享 X，靠手动 _propagate_xlim_to_siblings 易脱节（原始用 sharex，canvases.py:675）
4P1 标题堆叠：左侧竖排长通道名互相重叠成一团 通道名被设为旋转 90° 的左轴标签（_axis_handle.py:438，调用点 pg_canvases.py:511）；内嵌标签兜底仅在 widget_w<320 触发（pg_canvases.py:1592），正常宽度永不生效。原始用 bbox 重叠检测翻成左上角圆角●标签（canvases.py:937 / 967）——正是参考图样式
5P1 选中「分屏 / 叠加 / 游标」按钮后没有底色 :checked 背景是白底白字（#ffffff，style.qss:1196），按钮又 setFlat(True)（chart_stack.py:798,814），选中态在白色工具栏上不可见
6P1 没有网格线（参考图有虚线网格） plot_channels 从不调用 showGrid；网格只在图表选项对话框可达（_axis_handle.py:474）。原始默认画 #d7dee8 alpha .78 虚线（canvases.py:193）

8P1 坐标轴 / 曲线配色与原始不一致（无彩色刻度、无彩色左脊、无单位 chip、线宽 1.0 vs 1.05） PG 只设标签文字，不染 y 刻度 / 左脊（对比原始 canvases.py:689-691）；线宽 pg_canvases.py:495=1.0；叠加 emphasis 会改写 pen（:1248）

详细分析

#1 P0 重绘缓存「算了不画」——缩放不重采样 pg_canvases.py

模块文档自称的流水线是 set_xlim → positions_envelope → QPainterPath → cached pixmap → blit（:19）， 但最后一步 blit 从未实现。grep 显示 _curve_path_cache 只在 _refresh_visible_data（:1066）被写入、在失效函数里被清； 没有任何 paintEvent / drawPixmap 读取它，且 :1072 明确注释 「平移路径不要调 setData」。

因此实际上屏的曲线，永远是 _bind_channel 里那条 对全程 0–80s 做一次性 8000 点包络的 PlotDataItem（:495）。 放大到 2.5–8.5s 时只是把这段粗采样拉伸显示，细节不会变清晰； 而且 PlotDataItem 没有开 setDownsampling/clipToView。

修复方向：二选一并坚持一种渲染真相—— (a) 放弃自建 pixmap 缓存，改为在 _refresh_visible_data 里对每条 PlotDataItem.setData(env_t, env_s)（pyqtgraph 自身已是 C 级 QPolygonF 快路径， 配合 clipToView=True）；或 (b) 真正实现一个读取 _curve_path_cache 的 paint 层并把 PlotDataItem 隐藏。 推荐 (a)：更简单、零死代码，且天然支持缩放重采样。

关联测试 tests/perf/test_timedomain_pan_perf.py 的「14x」需重测—— 当前快是因为平移没产生可见重绘。

#2 P0 单 / 双游标实时未接线 pg_canvases.py / main_window.py

游标 HTML 计算函数 _emit_single_cursor_html（:1454）、 _emit_dual_cursor_html（:1477）已写好且有单测，但 实时 UI 中没有任何调用方。main_window.py:348-349 只做 set_cursor_visible / set_dual_cursor_mode 翻转状态位， 而这两个 setter（:576 / :583）注释自承「只存状态，画线是 T6 的事」。

结果：开启「单游标 / 双游标」后，点击图面不放置游标、画不出竖线、悬浮 pill 不更新。

修复方向：在画布上为每个 ViewBox 加 pg.InfiniteLine（A/B 两条）， 通过 scene 的 sigMouseClicked / SignalProxy(sigMouseMoved) 把光标 x 映射到数据坐标， 调 _emit_*_cursor_html 并 setPos 竖线；竖线需跨所有子图（与 X 同步联动）。

#3 P0 缩放只作用最上图 + 子图 X 不同步 pg_canvases.py / chart_stack.py

  • 滚轮缩放写死主轴：_handle_wheel_dispatch（pg_canvases.py:1412）全程用 self._primary_xaxis_ax，不管滚轮落在哪个子图——所以 Ctrl+滚轮 / Shift+滚轮 / 纯滚轮 永远改第 1 图。 而 _ModifierWheelViewBox（:94）本就持有事件源 ViewBox（self），只是没传下去。
  • 工具栏 pan/zoom 只设主 ViewBox：PgNavigationToolbar.pan()/zoom() （chart_stack.py:413-457）只对 _primary_view_box() 调 setMouseMode， 其它子图从不进入 Rect/Pan 模式，框选缩放对它们无效。
  • X 轴不同步：设计刻意不用 setXLink，改靠 sigXRangeChanged 手动 _propagate_xlim_to_siblings（:923）。图一第 2 图停在 2.5–8.5 而其余 0–80， 说明传播在初始构建 / 某些帧上脱节。原始 matplotlib 用 sharex=first（canvases.py:675）天然一致。
修复方向：(1) 把 _handle_wheel_dispatch 的目标从 _primary_xaxis_ax 改为「事件源 ViewBox 对应的 handle」（X 缩放仍同步到全体，Y 缩放只作用当前子图）； (2) pan/zoom 对 axes_list 中所有 ViewBox 设鼠标模式； (3) 评估直接采用 setXLink（其屏幕几何插值误差对本应用可接受，或在 padding=0 下校正）， 或保证初始 plot_channels 后立刻做一次 X 对齐。

内嵌标签逻辑其实已移植（_recheck_subplot_label_placement，:1594）， 但触发条件被换成了 widget_w < 320 的粗略宽度阈值（:1592）， 正常宽窗口永远走「外置竖排」分支。原始是真实 bbox 重叠检测 （canvases.py:937）+ 圆角框样式（_apply_inside_channel_labels，:967， boxstyle round,pad=0.24、白底 0.86、通道色边框）。

修复方向：子图模式下默认且始终使用左上角内嵌 TextItem（带通道色圆角边框、 ● 名称、ignoreBounds=True、随视图左上角定位），并清空旋转左轴标签； 去掉 320px 阈值。参考图样式即 _apply_inside_channel_labels 的复刻。

#5 P1 选中按钮无底色 style.qss / chart_stack.py

:checked 规则存在（style.qss:1195），但填充是 background-color:#ffffff（白）叠在白色工具栏上 → 几乎看不见； 按钮又 setFlat(True)（chart_stack.py:798/813）进一步抑制边框感。 本仓库已有蓝色强调色：激活图标 _ICON_ACTIVE = '#2563eb'、菜单选中 #e8efff。

修复方向：把 :checked 改成可见的强调填充——浅蓝底 #e8efff + 蓝字/蓝边 #2563eb（与工具栏激活态统一）； 确认 setFlat 下样式背景仍绘制（必要时去掉 setFlat 或加 WA_StyledBackground）。

#6 P1 缺网格线 pg_canvases.py

plot_channels 的三个分支（subplot / overlay / single）都没有调用 showGrid；网格仅经图表选项对话框 → PgAxisHandle.grid（_axis_handle.py:470）可达，默认关。 原始每个轴默认 ax.grid(True, color='#d7dee8', alpha=.78, ls='--', lw=.7) （canvases.py:193-194），参考图也有虚线网格。

修复方向：在 _bind_channel / 每个 PlotItem 建立后调 pi.showGrid(x=True, y=True, alpha=0.28)，并把网格笔触调成接近 #d7dee8 的虚线观感（pyqtgraph 通过 AxisItem.setGrid / 自定义 pen）。

#7 P1 每个子图都重复画 X 轴 pg_canvases.py

图一中 5 个子图底部各有一套 0–80 的 X 刻度，视觉冗余。 原始仅最底部子图显示 X 刻度与 Time (s) 标签，其余 tick_params(labelbottom=False)（canvases.py:692-695）。

修复方向：子图模式下，对非最底子图 pi.getAxis('bottom').setStyle(showValues=False) 并隐藏其 x label， 仅最底子图保留刻度 + Time (s)。

#8 P1 轴 / 曲线样式细节缺口 pg_canvases.py

  • 无彩色刻度 / 左脊：原始把 y 刻度、左脊都染成通道色、左脊 linewidth=2 （canvases.py:689-691）；PG 仅设标签文字。
  • 线宽：PG bind 用 width=1.0（:495），原始 lw=1.05。
  • 单位 chip：原始在轴顶横排画单位（_set_series_ylabel，canvases.py:255-264），PG 未复刻。
  • 叠加 emphasis 改写 pen：_apply_overlay_emphasis（:1248）会重设 pen 宽/透明度， 需确保不丢失原始通道色与线宽基线。
修复方向：新增一个 _apply_pg_axis_style(handle, color)，统一设置 左轴 setTextPen/setPen(color)、刻度色、线宽 2、单位顶标，并把 bind 线宽对齐 1.05； 作为子图 / 叠加 / 单通道三分支共用的样式入口（对应原始的 _apply_axes_style + _set_series_ylabel）。

建议修复顺序

  1. P0-#1 渲染真相（envelope 上屏 + 缩放重采样）——这是「画对」的地基，其它视觉项都依赖它先稳定。
  2. P0-#3 缩放 / 同步（滚轮目标轴 + 全 ViewBox 鼠标模式 + X 联动）。
  3. P0-#2 游标接线（InfiniteLine + 点击/悬浮 → emit）。
  4. P1-#4 标题 + #6 网格 + #7 X 轴 + #8 轴样式：合并为一个「样式对齐」批次，统一在 plot_channels 的样式入口处理。
  5. P1-#5 按钮底色：纯 QSS 改动，可随时并入。

说明：本报告为静态分析 + 截图比对结论，未启动实时 GUI。落地修复后需用同一组通道实跑对照 （缩放/平移/游标/分屏↔叠加切换/窗口缩放触发内嵌标签翻转）并截图复核。
