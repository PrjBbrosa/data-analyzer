# UltraView 窗口 / 交互与图片标注编辑器 review（对标 Snipaste）

日期：2026-11-13。版本：v8.4.7。分析 HEAD：`0614559a`。

本轮只做分析、探针测量和文档，**没有修改产品代码**。后续设计与实施见：

- spec：`docs/analyzer/specs/2026-11-13-ultraview-window-and-markup-interaction-hardening-spec.md`
- plan：`docs/analyzer/plans/2026-11-13-ultraview-window-and-markup-interaction-hardening-plan.md`

起因是用户的两张 Windows 截图和反馈：UltraView 打开后是一个 mini 缩略窗口；UltraView
与「图片标注」里很多操作不跟手，希望对标 Snipaste 做一次功能、逻辑和 bug review。

## 0. 结论

1. **mini 窗口：机制已确定，Windows 上的触发条件没有复现。** 截图里的窗口外框约
   162×191，对应客户区正好 160×160——这是 Qt 在顶层窗口「原生创建时宽高都为 0」时给的
   默认初始尺寸。`UltraViewSheet` 的尺寸只由共享几何规划器写入，而规划器自 `6b3105a5`
   起没有任何下限，窗口也没有 `minimumSize`，所以只要有一次规划结果退化成 0×0，就会得到
   这个 mini 窗口，并且之后不会自愈。**哪一步在用户机器上产出了 0×0，本轮在 X11 和
   Wine 下都没能复现**，需要一次 Windows 真机诊断（plan Task 0）。修复方向不依赖触发
   条件：给窗口、规划器、应用步骤各加一道下限，并在显示后校验一次。
2. **UltraView 有 4 个确定的逻辑 bug 和 3 类「不跟手」。** 失焦清理写在一个永远收不到
   事件的函数里（按住 Space 切走窗口后，左键拖动一直是平移）；Shift+滚轮整页跳；缩放
   手柄的光标只在卡片 1 px 边框上才更新、可见手柄有一半点不中；自由对象（便签 / 文字 /
   形状 / 画笔 / 连线）不能框选、不能多选一起拖、画笔和连线不能拖动。不跟手的三类是：
   卡片与自由对象拖动时本体不动、反馈按栅格跳；缩放成本随卡片数线性增长；平移会撞到
   「墙」，停手约 0.4 s 后才扩展画布。
3. **图片标注有 3 个 P1 和一批对标差距。** 任何工具只要按在已有标注上（包括空心矩形的
   内部）就变成移动它，而不是画新的；Esc 直接关窗并丢弃全部标注、没有确认；完全没有
   平移手势。其余是选择工具不能框选、快捷键提示写错、画完不选中、手柄随缩放变得很小、
   预览与成品样式不一致、悬停与选中态看不出区别等。对标 Snipaste 的差距集中在工具集
   （椭圆、马克笔、马赛克 / 模糊、橡皮擦）、右键结束、自定义颜色与线宽调节手感。

## 2. UltraView 打开成 mini 窗口

### 2.1 已确认的机制

- 截图中窗口外框约 162×191。按 Windows 10/11 的可见边框（左右下各 1 px、标题栏约
  31 px）推算，客户区是 160×160。
- Qt 的 `QPlatformWindow::initialGeometry` 对「原生创建时宽或高为 0」的顶层窗口，会把
  为 0 的那一维替换成 `minimumSize`（若设了），否则替换成默认值 160。实测：

  | 创建前的尺寸 | 显示后的客户区 | 证据 |
  |---|---|---|
  | `resize(0, 0)` | 160×160 | 【X11 真输入】【Wine】 |
  | `resize(0, 0)` + `setMinimumSize(640, 480)` | 640×480 | 【Wine】 |
  | `resize(1280, 0)` | 1280×160 | 【Wine】 |
  | `resize(0, 800)` | 160×800 | 【Wine】 |

- `UltraViewSheet` 的尺寸只有两个写入点：构造函数里的
  `fit_dialog_to_available_screen(self, parent, 1280, 800, min_w=800, min_h=560)`
  （`mf4_analyzer/ui/drawers/ultraview/sheet.py:54`），和每次 `showEvent` 里的
  `nudge_into_work_area`（`sheet.py:87`）。原生窗口就是在构造函数这次规划里创建的
  （`ui_kit/dialog_geometry.py:531` 的 `winId()`），尺寸等于规划出的客户区。
- 规划器没有下限。`client_budget`、`constrain_client_size`、`_clamp_frame`、
  `_shrink_unaccounted_frame` 都以 `max(0, …)` 收尾；`content_minimum`（800×560）按
  设计不能突破预算（`dialog_geometry.py:203-234`）；`_release_size_conflicts` 还会把
  布局约束设成 `SetNoConstraint`（`dialog_geometry.py:481`）。实测 sheet 的
  `minimumSize()` 是 0×0，可以被缩到 50×50。旧的硬下限是 `6b3105a5`（2026-09-05）
  移除的，那次提交说明里写着 Windows 原生验收未做；对应 spec
  `docs/analyzer/specs/2026-09-05-cross-platform-dialog-layout-spec.md` 的 G4 / G5 至今
  是 `UNVERIFIED`。
- 所以只要构造时的规划客户区是 0×0，窗口就以 160×160 出现；之后 `showEvent` 的 nudge
  只在窗口超出工作区时才动，160×160 不会超出，于是保持不变。**这条链路每一环都验证了，
  缺的只是「规划为什么会是 0×0」。**

### 2.2 没有复现的部分

规划客户区为 0×0，要求可用工作区减去边距和窗框后不剩空间，即 `availableGeometry()`
退化，或者存在一条本轮没找到的 Windows 专属路径。以下环境都得到了正常尺寸：

| 环境 | 结果 |
|---|---|
| 【X11 真输入】1920×1200，真实 `MainWindow.open_ultraview()` | 1280×800 |
| 【X11 真输入】1366×768 | 1280×723 |
| 【Wine】1920×1200，父窗口分别为正常 / 最大化 / 最小化 / 隐藏 | 1280×800 |
| 【Wine】1366×768 | 1280×723 |

待 Windows 真机排除或确认的假设（**都未验证**）：

1. 打开瞬间 `QScreen.availableGeometry()` 退化或过期（显示器热插拔、远程桌面重连、
   休眠唤醒后）。
2. 多屏混合缩放：窗口在主屏隐藏创建后移到另一块缩放不同的屏幕。
3. 真实窗框比隐藏时的估算值大。隐藏窗口用的是 `_ESTIMATED_TITLE_INSETS = (1, 28, 1, 1)`
   （`dialog_geometry.py:32`），Windows 实际约 (8, 31, 8, 8)。这会让 `showEvent` 的 nudge
   在常见笔记本分辨率上必然触发一次二次调整；它本身不应产出 0×0，但它是 X11 / Wine
   下没有走到的一条路径。
4. 用户看到的是窗口被还原 / 再次显示之后的状态：`showEvent` 对 spontaneous 的显示
   （从最小化还原）也会执行 nudge，且不检查最大化 / 最小化状态。
5. 巧合排除项：Windows 最小化窗口的宽度（`SM_CXMINIMIZED`）也是 160，但高度是标题栏
   高度，与截图的 160×160 客户区不符，可能性低，Task 0 顺带排除。

## 3. UltraView 功能、逻辑与跟手性

### 3.1 发现

| 编号 | 级别 | 发现 | 证据 |

### 3.2 实测正常、不需要改的部分

- Ctrl+滚轮缩放的锚点：6 格累计漂移约 1.2 px。【X11 真输入】
- 中键拖动平移：指针与内容 1:1。【X11 真输入】
- 平移每次移动约 1 ms（但每次移动有 2 次 `persist` 和一次小地图定位，可顺手合并）。【offscreen】
- 指针在卡片上方时普通滚轮可以正常滚动画布。早先一条「卡片上滚轮不滚动」的结论是合成
  事件的假象（非 spontaneous 的滚轮事件在 Qt 5.15 不向父级传播），已撤回。【X11 真输入】

## 4. 图片标注编辑器

用户截图 2 里画布全白。仅凭截图无法判断是源图本身空白还是抓图失败，需要用户确认当时
标注的是什么图；本轮在 X11 下用非空白图片打开编辑器，图片显示正常。

### 4.1 发现

| 编号 | 级别 | 发现 | 证据 |
|---|---|---|---|
| M-1 | P1 | **任何工具按在已有标注上都变成移动它。** `mousePressEvent`（`markup/view.py:38`）在分派工具之前先做命中，命中就 `_begin_move`。而空心矩形的内部也算命中（`markup_item_at`，`editor.py:628`）。实测：箭头工具从一个矩形框内部起拖，矩形被移走 (365,180)，没有画出箭头；序号、文字工具在框内点击什么都不产生；画笔在框内拖动不出线。在一块已标注区域里继续加标注基本做不到 | 【X11 真输入】 |

| M-5 | P2 | 快捷键提示与实际不符：工具提示用「工具 id 首字母」生成（`toolbar.py:195`），选择工具显示「选择 (S)」，实际按键是 `V`（`editor.py:1050`），按 `S` 无反应 | 【X11 真输入】 |
| M-6 | P2 | 画完不选中：新画的形状没有被选中，也没有手柄；想微调必须先切到选择工具再点它 | 【X11 真输入】 |
| M-7 | P2 | 手柄随缩放变小：手柄是 8 个场景单位的矩形（`editor.py:740`），2400×1400 的图在适应缩放 0.394 下只有约 5×5 屏幕像素。命中容差是按屏幕像素补偿过的（14 px），问题只在看不清 | 【X11 真输入】 |
| M-8 | P2 | 预览与成品不一致：所有工具的预览都是虚线（`view.py:219`），箭头预览没有箭头头部，画笔预览也是虚线。画笔预览的绘制耗时随点数增长（200 点 0.3 ms → 1200 点 5.4 ms） | 【X11 真输入】；耗时是 VNC 软件光栅下的读数 |
| M-9 | P2 | 悬停与选中的工具按钮看不出区别：`style.qss:3026-3037` 里 `:hover` 与 `:checked` 是两种几乎一样的浅蓝底 + 同色边框。截图 2 里「选择」和「箭头」两个按钮看起来都亮着 | 【读码】+ 用户截图 |

| M-11 | P2 | 窗口固定 960×640（`editor.py:157`），不看屏幕也不看图片大小，也没走共享几何规划器；小图打开即被放大（400×300 → 缩放 1.95），3840×2160 → 0.246 | 【X11 真输入】 |
| M-12 | P2 | 编辑器关闭后不销毁：没有 `WA_DeleteOnClose`，父对象是 `MainWindow`，关闭后 `sip.isdeleted` 仍为假，位图和场景一直占着内存；再次打开会新建一个而不关闭上一个（`window.py:1163`） | 【X11 真输入】 |

### 4.2 实测不是卡顿来源的部分

- 手柄的销毁重建：41 个选中项一起拖，每次移动平均 3.2 ms（61 次移动重建了 20336 个
  手柄对象）。可以优化，但不是用户感觉到的不跟手。【X11 真输入】
- 在 2400×1400 的图上拖一个 1000×700 的矩形：每次绘制约 3.9 ms。【X11 真输入】

这两个读数来自 VNC 会话的软件光栅，只说明量级，不是 Windows 上的帧时间。

用户感觉到的「不跟手」主要来自 M-1（想画却拖走了别的东西）、M-3（不能平移，只能反复
缩放）、M-6 / M-7（画完改不了、手柄点不到）和 M-8（预览和结果不一样），都是交互逻辑
问题，不是性能问题。

## 5. 对标 Snipaste

依据 Snipaste 官方文档（`docs.snipaste.com` 的「内置快捷键」「基础操作」「高级技巧」）。
**本轮没有运行 Snipaste**，下表右列里凡涉及手感的条目，落地前要在真实 Snipaste 上再
核对一次。

| 能力 | Snipaste（文档） | TraceLab 现状 | 差距 |
|---|---|---|---|
| 工具集 | 矩形、椭圆、折线 / 直线 / 箭头、画笔、马克笔、马赛克、高斯模糊、橡皮擦、文字 | 选择、裁剪、箭头、直线、矩形、画笔、文字、序号 | 缺椭圆、马克笔、马赛克 / 模糊、橡皮擦；多了序号和裁剪 |
| 在已有标注上继续画 | 新标注总是从按下处开始 | 按在已有标注上变成移动（M-1） | 逻辑缺陷 |
| 结束当前标注 | 鼠标右键单击结束当前标注的编辑 | 右键无作用 | 缺 |
| 线宽调节 | 滚轮、`1` / `2`、`[` / `]` | 只有 `[` / `]`，无上限；滚轮是缩放 | 手感差距；滚轮语义冲突，需要产品决策 |
| 颜色 | 大色块按钮可选任意颜色，含透明度 | 6 个固定色 | 缺自定义色 |
| 形状约束 | Shift 画正方形 / 正圆 / 45° 线；画笔中途按 Shift 画直线段 | `view.py:261` 有 Shift 分支，本轮未逐项验证 | 待核对 |
| 撤销 / 重做 / 清空 | Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z 清除全部 | Ctrl+Z / Ctrl+Y，有撤销栈；无一键清空 | 缺清空 |
| 完成 | Enter 复制并退出；Ctrl+C 复制图像；Ctrl+S 保存 | 「完成复制」「保存」按钮；Enter 只确认裁剪（代码注释写明是有意避免误触）；Ctrl+C 复制的是选中的标注 | 完成动作没有键盘入口 |
| 放弃 | Esc 中止 | Esc 无确认直接丢弃（M-2） | 逻辑缺陷 |
| 文字 | 拖文本框角点缩放，手柄旋转 | 双击编辑，无旋转 | 缺旋转（优先级低） |
| 像素级微调 | W / A / S / D 移动指针 1 px | 方向键移动选中标注 1 / 10 px | 语义不同，够用 |
| 画完再改 | 文档写明目前靠撤销 / 重做，「将来会支持直接的二次编辑」 | 可以用选择工具二次编辑，但画完不自动选中（M-6） | TraceLab 能力更强，入口更深 |
| 画布缩放 / 平移 | 截图 1:1 标注，没有这个概念 | 有缩放、无平移（M-3） | TraceLab 特有问题 |

TraceLab 的二次编辑、序号、裁剪和可撤销的对象模型比 Snipaste 文档描述的更完整；差距
主要在「按下就画」的确定性、结束 / 放弃的键盘语义和工具集。

## 6. 复现方式

真实输入探针的运行方式（探针脚本未入库）：

```bash
# X11 真输入
TMPDIR=/tmp DISPLAY=:1 QT_QPA_PLATFORM=xcb PYTHONPATH=. .venv/bin/python <probe>.py
# offscreen 插桩
TMPDIR=/tmp QT_QPA_PLATFORM=offscreen PYTHONPATH=. .venv/bin/python <probe>.py
```

探针做的事情：构造真实 `MainWindow` → `open_ultraview()` → 注入卡片或自由对象 → 用
`xdotool mousemove / mousedown / mouseup / key` 驱动 → 读模型状态、光标形状、滚动条值
和选择集。标注编辑器的绘制计时需要在**类**上替换 `_MarkupGraphicsView.paintEvent`
（sip 会缓存「没有 Python 重载」的虚函数，实例级替换不生效）。
