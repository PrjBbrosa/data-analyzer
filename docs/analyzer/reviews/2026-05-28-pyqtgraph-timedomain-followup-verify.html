二、你列的 4 个新问题（均成立）

P0功能/正确性 P1一致性 P2打磨

① P1 默认线条太细 真

bind 用 pg.mkPen(color=color, width=1.05)（pg_canvases.py:510）。 问题在于 matplotlib 的 lw=1.05 是点(pt)，pyqtgraph 的 width=1.05 是像素(px)—— 在高分屏上 1px 线又细又锯齿。叠加默认线宽 _overlay_default_lw=1.05 同源（:303 一带）。

建议：默认线宽提到 ~1.6–2.0，并开抗锯齿 （pg.setConfigOptions(antialias=True) 或建 PlotDataItem 时 antialias=True）； 同步调高 overlay 默认/选中线宽基线。

② P1 坐标轴密度调整无效 真

set_tick_density(x,y) 是空实现 return None（pg_canvases.py:857）。 检视器的密度控件经 main_window.py:459 / 1004 → canvas_time.set_tick_density() → 什么都不做。

建议：用 AxisItem.setStyle(tickSpacing=...) 或 AxisItem.setTicks() 把密度落到左/底轴；子图模式对每个 PlotItem 都设。

「类似功能再检查」→ 确实还有一批死/半死控件（详见第三节 Bug A）。

③ P0 取消标题/通道标签「还会跑」 真（对应图四）

内嵌通道标签是 pg.TextItem，建立时 setPos(x_range[0], y_range[1])—— 数据坐标（pg_canvases.py:1821），只在 plot_channels / resizeEvent 时重定位， 不随 pan/zoom 更新。所以平移缩放后标签停在旧的数据坐标上，飘到图中间（图四里两个 [diya luntai] ... 方框正是如此）。这就是「还会跑」。

建议：把标签锚到视口角落而非数据点—— text_item.setParentItem(vb) 后用像素锚点（ViewBox 局部坐标左上角恒为 0,0）， 或连 vb.sigRangeChanged 每次回调把 setPos 更新到当前 viewRange 左上角。 原始 matplotlib 用 transform=ax.transAxes（轴比例坐标）天然不漂。

④ P1 叠加状态坐标轴「消失」 真

叠加分支只建一个 PlotItem + 一个 ViewBox，把所有通道塞进同一条共享 Y 轴 （pg_canvases.py:394-403）。而原始 matplotlib 叠加是 每通道一条 twinx 轴（左轴 + 多条向外偏移的右轴，各自独立 Y 缩放、各自染色， canvases.py:702-733）。后果：

  • 多条彩色 Y 轴变成只剩一条 → 你看到的「坐标轴消失」。
  • 所有通道被压到同一 Y 尺度 → 量级小的通道被压成贴边平线（看不清）。
  • 那条仅存的左轴被 _apply_pg_axis_style 在循环里反复改色，最终停在最后一个通道的颜色与标签，语义错乱。
建议：叠加模式恢复「每通道独立 Y 轴」——pyqtgraph 惯例是为每条曲线建独立 ViewBox + AxisItem，用 updateViews() 把它们和主 ViewBox 的几何/ X 绑定 （pyqtgraph 官方 MultiplePlotAxes 示例）。这是本轮最大的结构性缺口，工作量也最大。

三、我新发现的 Bug

A P1 图表选项对话框对 PG 画布有一批控件是死的

根因：ChartOptionsDialog.self.ax = getattr(self.handle,"axes",None)（dialogs.py:311）， 而 PgAxisHandle 没有 .axes 属性 → self.ax = None。 凡是经 self.ax 的逻辑在 PG 画布上全失效：

控件 / 行为代码PG 现状
「重新生成自动图例」dialogs.py:654-659（self.ax.get_legend_handles_labels()）死控件，点了无效
网格复选框初始态dialogs.py:565-566（读 self.ax...get_gridlines()）读不到，永远显未勾（即使网格已开）
X/Y 比例下拉初始态dialogs.py:568-569（读 get_xscale/yscale）读不到实际值；不过应用 log 经 set_xscale→setLogMode 仍生效
曲线改色时同步轴脊/刻度色dialogs.py:800（raw_line.axes or self.ax）只改曲线色，轴脊/刻度不跟着变色
建议：给 PgAxisHandle 把这些能力补进协议（读网格态 / 读 scale / 轴脊染色 / 图例）， 让对话框走 handle 而非 self.ax；或在对话框里对 handle 类型分支。 这正是你说的「类似功能再检查」的那一批。

B P2 pixmap 路径变成纯浪费

T1 让 setData 成为真正的渲染真相后，_refresh_visible_data 里每帧仍调 _build_painter_path + _render_path_to_pixmap 写进 _curve_path_cache（:1260-1264）， 但没有任何读取方。这是平移热路径上的无效计算，部分抵消了性能收益。

建议：从 _refresh_visible_data 删掉 pixmap/path 构建（连同缓存字段）， 或明确标注为关闭的实验路径。

C P1 游标开启时拖动平移可能失效

eventFilter 在 _cursor_visible 为真时吞掉 MouseMove并 return True（:955-957）， 事件不再下发给 ViewBox 的拖拽-平移逻辑。即「单游标/双游标」开着时，左键拖动平移会被游标 hover 抢走。

建议：仅在「未按下左键拖拽」或「非 pan/zoom 模式」时消费 MouseMove； 按下拖拽时放行给 ViewBox。

D P2 设标题会出现「双标题」  ·  E P2 Home 后子图 X 可能脱节

  • D：对话框设标题 → PgAxisHandle.set_title→pi.setTitle 在子图顶部居中显示一个标题， 而左上角内嵌通道名标签仍在 → 同一子图出现两处标题文字。
  • E：PgNavigationToolbar.home() 对每个 ViewBox 各自 autoRange()（chart_stack.py）， 各子图按自身数据 X 范围复位；若通道时间范围不同，Home 后子图 X 不再对齐 （原始 sharex 不会）。建议 Home 后强制做一次 X 对齐传播。
