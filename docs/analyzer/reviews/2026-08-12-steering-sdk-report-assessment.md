# 转向 SDK 扩展报告评估与裁决(2026-08-12)

**评估对象**:`docs/analyzer/reviews/2026-08-12-steering-system-sdk-extension-brainstorm-report.html`
(Codex 侧产出,约 2 万字正文;引用的 11 个代码文件全部与树内现状相符,是基于真实
代码阅读的提案,不是泛泛之谈。)

**结论一句话**:报告里的五项能力作为**产品功能**成立、值得按序做进标准版;
"SDK / 插件运行时"这层**机制包装整体搁置**,不建。

## 1. 报告答对了什么(采纳)

- **API 切层正确**:全文钉死不把 `MainWindow` / Qt 控件 / Canvas 当公共 API,
  PlotDocument 由宿主渲染。宿主拥有渲染意味着 ink 预算、AA 闸门、光栅准入全部
  留在宿主手里,性能护栏不被扩展代码绕开——这是提案里最对的一个设计决定。
- **声明式优先**:"多数客户需求停留在 Workflow Pack(数据)层,缺算法才注册
  Operator(代码)"——方向正确。
- **Cache Key 必须扩维**:`ui/analysis_cache.py` 现有键不含算法/参数/版本身份,
  任何 Workflow 化之前必须先加,否则升级后复用旧结果是最隐蔽的错误放大器。
- **五项优先级排序**("角色解析第一,越自动越危险"的论证)、Dry-run 三步 UX、
  前后对照度量清单、风险表(含"项目阈值不得冒充法规")——全部采纳为将来做
  对应功能时的设计输入。
- 报告诚实度高:不编造收益百分比,覆盖数图表自注"方向性判断非实测",
  ISO/SAE 只用公开摘要。

## 2. 报告的结构性问题(修正)

- **P0 与"声明式优先"自相矛盾**:一边论证多数需求是数据 Pack,一边把完整的
  Python 代码插件运行时(Manifest、版本协商、异常隔离、权限、签名)设为 P0 前置。
  正确结论应反过来:地基收缩为"版本化 Pack Schema + 加载器 + 校验",Pack 是
  数据文件。数据文件不需要异常隔离/权限/签名,不碰 PyInstaller 动态 import 的坑,
  分发即发一个 JSON。
- **朋友规模不需要兼容矩阵**:SemVer + 弃用周期 + 版本协商是为管不住的第三方
  生态设计的;N≤5 的朋友分发只需要"Pack 写 schema 版本号,宿主不认就报清晰错误"。
- **落地遗漏的仓库契约**(报告未提,实施时绕不开):
  - batch 方法集合 Registry 化必须仍经 `_RunReporter` 单点
    (`tests/test_batch_run_reporter.py` 看守),不得给扩展路径开第二份 emit/record;
  - WorkspacePlan 事务应用要以具名协作对象持有状态,别触发状态所有权棘轮
    (`tests/ui/test_main_window_state_ownership.py` 白名单只许缩小);
  - `ui/view_state.MAX_VIEWS = 12`:批量建 View 的 Plan 撞上限时的语义
    (拒绝/复用/腾位)必须进校验,否则"失败整体回滚"变高频路径。

## 3. 核心裁决:功能是真的,机制是虚的,"别人来扩展"是幻觉

把**功能本身**与**第三方代码挂载机制**分开:五项功能一行插件代码都不需要
(角色字典=数据文件,切段=内置状态机+参数,KPI=表达式层 `channel_math` 已有,
模板=序列化配置)。SDK 机制只在"存在控制不了、又不能进主仓库的代码"时才必要,
当前需求的真实路径是"朋友提需求 → 本仓库改 → 发新包",瓶颈不存在。

"别人扩展提效"的现实画像分三层:**用**(100% 的人,提效来自功能本身)、
**改配置**(少数人,前提是格式傻瓜、报错清晰——这层值得设计,叫可配置不叫 SDK)、
**写代码**(现实预期为零;"客户封装私有 Pack"实操会变成"客户把需求微信发过来")。
作者永远是维护者本人,内部模块化(现有护栏已保证)就是所需的全部"SDK"。

## 4. 行动清单

**做**(按价值/成本排序,当普通 feature 进标准版,配置一律用户可编辑数据文件):

| 序 | 功能 | 地基 | 备注 |
|---|------|------|------|
| ① | 通道角色字典 + 数据预检 | `io/source_adapters.py` 逻辑源体系 | 唯一单机自用即回本的一项 |
| ② | 工况自动切段(状态机+画布预览) | `signal/` 纯函数 + 画布预览层 | 与 FRF plan 的指令分段器重叠,可顺路做 |
| ④ | Workspace 模板(一键重建 View 布局) | `ui/view_state.py` 已可序列化 | 成本偏低,顺手该做 |
| ③ | CaseSet 多工况对比 + KPI 矩阵 | `batch_grouping` / `batch_statistics` | 批量回归最大头,成本最高(新 UI 面) |
| ⑤ | 导出 Writer 注册 | `batch_output` 原子写入复用 | 等真实客户格式需求出现再做 |

**不做**:插件运行时、Manifest、版本协商、Operator 注册表——一个都不建。

**留口**:若日后出现"保密算法不能进仓库"或"维护者响应不过来"的实锤,再按
数据 Pack 路线补分发机制;届时五项功能已内置,Pack 只是把已有配置打包,增量小。

**先决问题**(报告自己列的第一问,也是任何后续动作的闸门):第一批朋友是谁、
分析什么、数据什么格式——决定首个角色字典和试点场景,只有产品所有者能答。
