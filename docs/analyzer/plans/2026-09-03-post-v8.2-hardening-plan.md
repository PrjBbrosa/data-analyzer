## 0. 通用规则（每个实施者必读）

1. 改前先跑本 Task 的 owner 测试拿基线，**不要跑全量、不要跑整个 `tests/ui`**。
2. 红测先行：本 Task 的新看守测试在改生产代码前必须能红（改法见各 Task）。
3. 完成后跑：owner 测试 + 下列机械护栏（一条命令）：
   ```bash
   TMPDIR=/tmp MPLCONFIGDIR=/tmp QT_QPA_PLATFORM=offscreen PYTHONPATH=. .venv/bin/python -m pytest \
     tests/ui/test_main_window_state_ownership.py tests/ui/test_pg_canvas_backref_invariants.py \
     tests/ui/test_import_boundaries.py tests/test_signal_no_gui_import.py \
     tests/test_batch_render_import_boundary.py tests/test_native_import_boundaries.py \

     tests/ui/test_no_lambda_signal_connections.py tests/test_conftest_autouse_scope.py \
     tests/ui/test_qsettings_isolation.py -q -p no:cacheprovider
   ```
   基线 45 passed / 1 skipped；任何棘轮数字只许缩小。
4. 只改 owner 白名单内的文件；越界立即停线报告，不得顺手重构。
5. **不要碰工作区里已有的 tracked 删除与 untracked 文件**（`assets/**`、
   `mf4_analyzer/help/assets/*.png`、`docs/reports/*.png`、根目录 `ssh-keygen*`、
   `code_stats_report.html`），不还原、不提交、不 `git add -A`。用 `git add <显式路径>`。

7. 禁止新增 `.connect(lambda`、宽泛 `except Exception`、`getattr(self, "_x", False)`
   类静默守卫、多文件写同一 `MainWindow` 属性。
8. 提交信息按既有约定 `fix(ui): …` / `fix(ultraview): …` / `test(ui): …`，正文引用
   review 编号（如 `Closes review D1`）。
