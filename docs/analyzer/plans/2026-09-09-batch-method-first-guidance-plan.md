## 1. 目标与范围

用户打开面板时，先理解分析类别决定目标和参数，再完成文件、目标、参数与输出配置。采用已确认的 B 方案：把现有五个分析方法移到整个三栏上方，以紧凑文字页签呈现，并明确标为第 1 步。

保留当前三栏及其成熟控件：左侧文件与目标、中间分析预设与完整参数、右侧输出设置。保留文件列表、FRF 配对编辑器、信号选择器、阶次转速设置、预处理、图表组织、坐标范围、刻度字体、预览和运行入口。方法置顶后，中间栏从分析预设或当前方法的参数内容开始。

本轮只调整方法选择器的承载位置、呈现和轻量提示；不重排三栏内部业务控件，不改分析计算、参数默认值、目标匹配规则、方案格式、持久化优先级或运行判断。分析预设按钮不套用方法页签样式。

HTML 用于确认布局和交互意图，不是参数规格。示例中的默认频响、信号名、文件数量和输出数量不得写入产品逻辑；当前真实 `MethodButtonGroup` 默认是 `fft`，继续保持。原型的体验场景切换、重置场景、显示引导开关属于演示工具，不加入正式程序。

## 2. 已确认的 UI 契约

### 2.1 整体结构

```text

01 先选分析方法    时域  频谱  时频  阶次  频响    方法与下一步提示
02 文件与目标                03 分析参数                    04 输出
现有左栏                     现有中栏                      现有右栏
现有状态 / 可选定位入口                                  关闭 / 预览 / 运行
```

- 方法行固定在滚动区域之外，切换三栏滚动位置时仍可见。
- 三栏继续使用现有 `29:39:32` 比例和各自纵向滚动区域。
- 五个方法顺序、键和名称保持 `time/时域`、`fft/频谱`、`fft_time/时频`、`order_time/阶次`、`frf/频响`。
- 当前类别用蓝色文字和短下划线标识；取消该方法组原来的侧边标记和选中圆点，不扩展为整行等分大按钮。

### 2.2 尺寸与层级

- 方法行在常规字体下目标高 40 个 Qt 逻辑像素；五个页签总宽约 300–340 个逻辑像素，每项点击区域至少 28 像素高。字体较大时由实际字体度量保证完整文字，不以裁字换固定宽度。
- 现有工具栏 36、三栏状态条 40、底栏 50 的高度契约保留；不得套用 HTML 演示工具栏的高度。
- 提示与页签同一行，提示可收缩、省略并通过 tooltip 提供全文。优先保住方法名称与点击区域，不增加第二行帮助横幅，不在紧凑窗口中把三栏堆叠。
- 首次提示使用淡蓝背景、蓝色 01 标记和一条短句；不闪烁、不遮罩、不弹向导、不抢焦点。

左侧目标区标题随真实方法更新；选择控件保持原对象和既有显隐逻辑。

| 方法 | 目标区标题 | 保留的真实输入要求 |
| --- | --- | --- |
| 时域 | 分析信号 | 现有信号选择；自定义 X 依赖继续走原参数链 |
| 频谱 | 分析信号 | 现有信号选择 |

## 3. 引导状态与业务状态分开

引导是建议操作顺序，不能变成新的运行条件。默认类别可直接沿用；用户不必为了完成引导重复点击当前类别。

由 `BatchSheet` 单独持有一个本窗口的引导状态，显式初始化；只区分“需要起点提示”和“已进入配置”。它不进入 `AnalysisPreset`、BatchRecipe、JSON、QSettings 或 MainWindow。

| 事件 | 引导结果 | 业务行为 |
| --- | --- | --- |
| 新建窗口，仅有默认配置或输出偏好恢复 | 显示起点淡蓝提示 | 保持现有默认方法，不主动清空文件或参数 |
| 用户点击当前已选方法 | 消退起点提示，显示当前方法与下一步 | 不触发额外 `methodChanged`，不清除预设状态 |
| 用户点击另一个方法 | 在现有方法切换事务结束后更新提示 | 原切换链只执行一次 |
| 用户直接成功添加/选择文件、修改目标或参数 | 视为沿用当前方法，进入配置提示 | 不要求先点方法，不新增方法切换 |
| 取消文件或方案对话框、后台探测回调、恢复输出偏好 | 不作为用户确认方法 | 不凭这些事件清掉首次提示 |
| 成功同步单次分析、成功导入并应用完整方案 | 直接显示当前方法与剩余问题 | 已有配置可直接预览/运行 |
| 同步/导入取消或失败 | 保持原引导及配置状态 | 沿用现有错误反馈 |
| 配置完整 | 普通页签；提示可预览/运行 | 运行与预览继续由既有验证决定 |
| 运行中 | 显示当前方法，不再提示继续配置 | 运行、进度、中断、关闭规则保持原实现 |
| 关闭并创建新窗口 | 按新窗口实际进入路径重新初始化 | 不持久化“教学已完成”标志 |

区分主动动作与程序初始化：不能把通用 `changed` 或每次 `set_method()` 都当作用户操作。提供独立的用户激活通知，或在已有用户动作的成功出口更新引导状态；无关控件的普通聚焦不算确认。

### 3.1 状态与定位的真相源

- 在现有 `_recompute_pipeline_status()` 完成依赖同步后，从本次已有文件状态、`preflight_issues`、运行状态及输出预览事实投影提示。
- 提示只读取校验结果，不新增另一套 `is_runnable()`，不为了提示额外调用 runner、数据探测或生成预览。
- 首次提示优先解释方法；进入配置后优先展示正在解析、文件/来源问题、当前方法目标问题，再展示参数或输出问题。以现有阻塞判断为准，不能把可恢复警告擅自升级为禁止运行。
- 底栏在空闲且存在可定位问题时提供一个轻量文字入口：“去添加 / 去选择 / 去检查”。它只滚动到当前真实控件并聚焦，不修改配置、不自动打开文件对话框、不新增目标。
- 定位对象根据当前方法和当前问题重新解析，避免持有已删除的 Qt 包装对象。字段不可定位时保留文字说明，不能跳到错误控件。
- 自动滚动只发生在用户点击定位入口后；单纯选择方法不强制跳转滚动区域。
- 输出数量继续使用现有实际预览结果；不能复制 HTML 的示例计数公式。预览未解析时表达待确定，不能猜测数量。

### 4.1 必须保持的事务与兼容约定

```text
MethodButtonGroup.methodChanged
  → AnalysisPanel._on_method_changed
    → DynamicParamForm.set_method(..., emit=False)
    → AnalysisPanel.methodChanged
      → InputPanel.set_method
      → OutputPanel.apply_method_defaults
      → BatchSheet._on_recipe_method_changed
      → _schedule_pipeline_recompute
```

- 用户重复点击当前方法不发 `methodChanged`；显式程序调用 `set_method(current)` 仍保留原刷新约定。
- 引导用的用户激活通知不得再次调用 `set_method()`。提示在依赖完成后读取状态，避免把过渡状态当成最终配置。
- `apply_preset()` 仍是完整方案应用边界；预设卡片的局部应用和 `apply_params()` 的增量语义不变。
- 保留 source/channel 的复合身份、逻辑来源展开、同名通道、缺失信号、FRF 配对和 RPM 的现有契约。
- 方法往返切换的参数/目标保留策略按当前实际实现验证，不承诺 HTML 演示中的逐方法独立缓存。若基线本身存在缺陷，记录并区分，不在布局任务中顺带改变语义。
- 不改 `batch.py`、计算、输出、渲染器、工作线程或持久化结构；不扩展 MainWindow 状态所有权。
