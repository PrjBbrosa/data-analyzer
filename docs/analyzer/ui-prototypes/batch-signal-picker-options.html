TraceLab · 批处理 · 目标信号选择器

一个控件干了三件事，所以哪件都不顺手

现在的「目标信号」框同时是已选摘要、搜索输入和展开按钮。 三个职责抢同一行 38px 的空间，于是有了跳位、拥挤和看不清。下面先把问题定位到代码， 再给三种可以真的点一点的替代做法。

现状诊断

五个症状，四个根因

01
箭头是字符，不是图形
按钮文字直接用 "⌄" / "⌃"，字重、基线、光学中心全交给字体决定， 再加 26×28 的蓝色实底方块，视觉上比它该有的份量重得多。signal_picker.py:177
02
白底控件落在浅色面板上，边界只靠 1px 灰线
background:#fff + 1px #cbd5e1，面板底色本身也接近白， 输入区和背景几乎没有明度差，看不出哪里可以点。signal_picker.py:130
03
选中之后拥挤：chip、+N、光标、placeholder 挤一行
chip 最宽 180px、搜索区最少 42px，剩下的靠 elidedText 硬切。 第二张截图里 chip 后面那半截灰字，就是 placeholder「继续搜索…」被压成了两个字。 signal_picker.py:459
04
删掉关键字，输入框跳回右边
一开始搜索就把 chips 全部隐藏（visible_count = 0），输入框顶到最左； 清空搜索后 chips 重新出现，又把输入框推回右边。 下面那个复刻里实测：选中 3 个信号时，输入框左边界来回位移 339 px——光标在打字过程中横跨了大半个控件。 signal_picker.py:434
05
弹层要靠一句话解释自己
弹层顶部写着「直接在上方原通道框输入」——需要用文案教用户去别处打字， 就是这个交互没有自解释。而且弹层宽度只取 max(280, 触发器宽度)， 长信号名在列表里同样被切掉。signal_picker.py:278

替代方案

三种做法，从最小改动到最适合长信号名

A · 摘要行 + 弹层内搜索

最小改动
收起时只做一件事：显示选了什么。搜索框搬进弹层，打开即自动聚焦。 输入框从此在固定位置，永远不会被 chips 推走。
▸
点开后直接打字即可筛选；搜索框位置固定，删关键字不会有任何跳动。列表比触发器更宽，长名字不再被切。
Option A
滤波关闭 · 保留原始数据
解决
职责拆开后，收起态不再拥挤；搜索框零位移；弹层可以自由加宽、加底部操作条。改动集中在一个文件里。
代价
多一个输入框（这正是当前设计刻意回避的，但它其实是 Qt / Element / Ant Design 的通用范式，用户没有困惑成本）。选完仍要靠 chip 判断选了什么，超过 3 个还是得看 +N。
解决 0102 0304 05

B · 标签输入框

保留单控件
像邮件收件人栏：chips 和光标待在同一个框里，光标永远在最后一个 chip 之后。 搜索时 chips 不消失，框会长到两行再滚动。⌫ 直接删掉上一个 chip。
▸
试着在已经选中几个的情况下打字——chips 留在原地，光标始终跟在后面。空输入时按 ⌫ 可回删。
Option B
滤波关闭 · 保留原始数据
解决
保住了「一个框搞定」的紧凑感，也彻底消除跳位——因为 chips 从不因搜索而消失。键盘流很顺。
代价
行高会变（1→2 行），批处理面板是定高紧凑布局，下面几行会被推动；QFormLayout 里这类高度变化最容易引出新的排版抖动。信号名太长时两行也塞不下几个。
解决 0102 04 部分 0305

C · 信号选择面板

推荐
表单行退化成一个摘要按钮，点开一块真正够用的面板：左边搜索 + 分组列表， 右边是已选清单（完整名字、逐条可删）。筛出来的一批可以一键全选。 分组按量纲前缀（m 扭矩 / n 转速 / w·ph 角度 / i·u 电压电流） 而不是模块名——模块名几乎一条一个，分了等于没分。
▸
输入 torq 后点「全选 N 条」——这是当前实现完全做不到、但选 24 条通道时最需要的动作。
Option C
滤波关闭 · 保留原始数据
解决
唯一能完整显示 40+ 字符信号名的方案；分组和批量选择在通道数上百时是刚需；表单行永远只有一行摘要，再多选也不会撑开面板。
代价
最重：多一层浮层，要处理焦点、Esc、点击外部关闭。勾选与确认之间多一次「完成」动作（也可以做成即时生效，就没有这一步）。
解决 0102 0304 05
横切细节

不管选哪个方案，截断方向都得换

EPS 通道名的区分信息全在后半段：_xds16 / _gdf32 是类型后缀， 量名在中段偏后，而前缀 Rte_ 每条都一样。现在用的是右截断，等于优先保留最没有信息量的部分。

现在 · 右截断ElideRight
  • Rte_ActRetPlausi_mActiveReturnMo…
  • Rte_ActRet_mActiveReturnMotorTo…
  • Rte_MosfetTemperatureCalculatio…

前两条肉眼无法区分——它们其实是完全不同的两个通道。

改成 · 中间截断ElideMiddle
  • Rte_ActRetPlausi_…ReturnMotorTorque_xds16
  • Rte_ActRet_…ReturnMotorTorq4Chk_xds16
  • Rte_MosfetTemp…_cPCBTemp_xds16

模块前缀和量名后缀同时保住，一眼能分辨；成本只是把 Qt.ElideRight 换成 Qt.ElideMiddle。

建议

先做 A，把 C 留作「更多」入口

A 用一天的量就能把五个症状全部按下去，而且改动完全封在 mf4_analyzer/ui/drawers/batch/signal_picker.py 里， set_selected / selected / selectionChanged 这套外部接口一行不用动， tests/ui/test_batch_smoke.py 里断言 _overflow_label 的用例改几处即可。

但你这批通道名普遍 30–46 字符、单个来源就有 24 条以上，A 的弹层再宽也只是缓解。 所以把 C 作为第二步：在 A 的弹层底部加一个「在面板中选择」入口，需要批量筛选和看全名时才打开。 两步之间不冲突，A 的数据层可以原样复用。

  • 第一步　把内联搜索移进弹层并自动聚焦，收起态改为只读摘要行，删掉那句「直接在上方原通道框输入」的提示。
  • 第二步　箭头改用 QPainter 画 chevron（或 ui_kit/icons.py 里出一个 SVG），去掉蓝色实底，只在 hover 时给底色。
  • 第三步　收起态底色改成比面板略深的凹陷灰，聚焦时转白 + 蓝边；这样静止状态也能看出这是个可点区域。
  • 第四步　全局把 chip 和列表项的 Qt.ElideRight 换成 Qt.ElideMiddle，弹层最小宽度从 280 提到 420。
  • 第五步　弹层底部加一行：左边「已选 N」，右边「全选筛选结果 / 清空」——这是 24 条匹配时最省事的一步。

RPM 通道那一行用的是同一个 SignalPickerPopup(single_select=True)，单选态下 chips 逻辑本来就用不上， 改成摘要行之后反而更干净——顺手一起收掉。
