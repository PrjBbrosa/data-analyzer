UltraView 应该属于 View 栏。

下面三种方案都放在 View 行：区别不在“放不放”，而在它是紧跟创建 View 的动作、常驻在栏右端，还是故意伪装成一个普通 Tab。

共同前提UltraView 跨 View 对照、只读且可回到原 View；因此入口必须贴近 View 集合，但不能让人误判它本身是一个可编辑 View。
VIEWPORT 点击每个 UltraView，查看打开 Board 时的提示层。
A · RECOMMENDED

紧跟「+」的 Board Chip

先创建 / 整理 View，紧接着进入跨 View 总览：流程连续，但仍明确是一个独立动作。

渐变最抢眼，却错误地强化了「第 N 个 View」印象。

渐变只用于身份，不用于状态

按钮底色、边框与禁用态仍遵循 TraceLab 的蓝灰体系；渐变只给 UltraView 字标和极细的激活标记。

固定动作，弹性文字

窄窗口先压缩其它 View、再进溢出；UltraView 字标可以收成图标，但 + 和入口都必须保留。

不要制造「第六个 View」

板是跨 View 的只读投影，不是新的数据或分析工作台。入口应有自己的图标和 tooltip，而不是标准 tab chrome。
