批处理谱图切片 · 目标渲染效果

2026-08-03 v3 · 配套 docs/analyzer/specs/2026-08-03-batch-heatmap-slice-and-stat-marker-design.md
谱图与切片曲线由同一份合成矩阵实时绘制 —— 切片确实是矩阵的某几行 / 某几列，不是画出来的示意。

1固定时间 · 3 个位置

一次只切一个维度，页面恒为 两行（6 : 3）。3 个时间位置在同一张切片图里叠加， 主图上 3 条同色竖线，图例在右侧 colorbar 占位栏。

暖色 = 固定时间 竖线 + 「幅值 vs 频率」。曲线与它的标记线同色，不看图例也知道谁出谁。
幅值轴走 nice step 先剔掉 −6153 dB 的 DC 死区，再按 nice step 把两端向外取整 —— 轴端读出来是 −100 / −90 / … / −30，不是 −99.12 / −34.38。
图例占零数据面积 右侧占位栏是 X 轴对齐的副产物，本来空着。图例进去代价为零 —— 这就是「不需要自适应加宽」的直接理由。
上限 4 个位置 约束来自主图：4 条标记线已是热力图不被盖住的上限。右栏纵向其实能放 6 条。
白色底衬 每条标记线是 3.6 px 白线打底 + 2.0 px 彩线，按 1920 px 导出尺度定 （不照抄单文件屏幕画布的 1 px）。turbo 下纯红在局部会完全消失。
切片关闭 → 回到一行 与改动前逐字节相同。既有预设的 fingerprint 和产出都不受影响。

同一份数据 · 固定频率 · 2 个位置

换个维度，布局不变，只有轴标签、曲线内容和线的方向变。 冷色 + 横线；切片横轴是时间，与主图共享，可以竖着直接读。

为什么不允许两个维度同时切：没有工况需要在同一张报告图上对比这两个维度。 「t=15 s 的频谱」和「620 Hz 随时间的走势」是两个独立的问题，硬塞进一页只会让读者 先花时间分辨哪条线属于哪个维度。要两个都看就跑两次 —— 得到两张各自干净的图。

Order-vs-Time 的差异

结构完全同构，只有 Y 轴物理量换成阶次：主图纵轴 Order、 固定时间切片的横轴 Order、图例栏头写「固定阶次」、值写 6.00（无单位）。

4时域统计极值标记

根因不是配色：ScatterPlotItem 在 pxMode 下按设备像素绘制， 批处理的 3× 超采样从不设置 resolutionScale， 于是 18 px 的标记画进 3× 画布、缩回后只剩 ≈6 px。 修法是超采样期给散点开 export mode，再换成 cursor 的实心红绿点。

现状 空心圈 · 近白填充 #fff7ed / #ecfdf5 · 名义 18 px，出图 ≈6 px
目标 实心 #dc2626 / #16a34a · 白描边 1.6 px · 名义 11 px，出图 ≈11 px
卡片表头同步 「最大值」#c2410c → #b91c1c， 「最小值」#0f766e → #15803d，否则点和表对不上
