这屏回答了"我怎么开始一次采集"

  • A2L 树即是你说的"选参数和变量名"。左边支持搜索 + 勾选，地址 / 单位 / 类型直接读 a2l_probe.py 解析的 MeasurementSummary。已选 12 项的预估带宽实时算出来 (14.4 kB/s)。
  • 中间是"已经选了哪些信号"的可视化预览。 每张卡片留出 32 px 高的小图表区域——录制开始后这块就是该信号的 live preview，停下后这就是该次录制的迷你回放。
  • 右边是录制参数（触发、buffer、输出文件名模板）。 数据源 radio 里"Vector / CAN replay / 合成"对应当前 can_logger/p0/ 的 stub 状态——macOS 上自动落到合成或 replay，Windows 上点亮 Vector，UI 一样。
  • Arm vs 立即开始：Arm 进入触发条件等待（适合台架场景"踩油门到 3000 rpm 才开始记"）；立即开始是默认快捷动作。

这屏回答了你的"实时数据流"要求

  • 主区是 5 条 live strip（点 last 30s / last 5min / 全程 切窗口）。每张图右上是当前瞬时值用大字号 + 等宽字体显示——台架前一米外的人也读得清。同窗口可滚动看全部 12 通道。
  • 左栏成为"信号 · 实时值"快速看板。点击信号 = 在主图聚焦它。颜色和左栏 swatch / 主图 stroke 一致，跟 Analyzer 的 _palette.py 是同一套配色。
  • 右栏切到"质量监控"：写盘速率、缓冲、丢帧、bus load、磁盘空间——录制时唯一需要紧盯的几个数字，每个有"健康 / 警告 / 危险"语义颜色。
  • 顶栏左上的 REC 00:01:47 红色脉动指示器是状态唯一来源真理。 不管 toolbar 切到哪个 mode、滚到哪一行，这个指示器都告诉你"还在录"。
  • 底部 Stop & 复盘 是大号红色主按钮。 点了之后自动停掉 recorder、关闭文件、跑 preflight、弹复盘模态（见 SCENE 3）。

为什么把 Preflight 和 Manifest 折进模态而非独立 mode

  • 这是录完后的最自然时刻。 你刚知道文件长啥样，对它的 quality / scenario 印象最清楚。这时候让你填 4 个字段是合理的；过了 1 小时再来填，要重新打开文件、重新看一遍——人会偷懒不填。
  • Preflight 不是单独的"工序"。它就是录制完成后的"自动健康检查"，应当无需用户操作。复盘模态展示结果，用户只在出错时关心细节（点开 problems 列表）。
  • 不强求填字段。 点"保存并归档"按钮就归档（manifest 字段尽量自动补全）。点"丢弃"就当没录过——bench 上误触 Record 的情况很常见，需要这个出口。
  • "在 Analyzer 打开"按钮是跨窗联动：刚录的文件直接喂给 Analyzer 进程做信号分析。这是 A 双窗设计的最大价值兑现点。

这就是你截图里那张表 — 现在它在它该在的地方

  • 开发流程里只会偶尔进来： 想找上个月的 ripple 数据做对比、查 SHA 还对不对、看哪些文件应该归 golden 数据集——roadmap §3 里说的那些"按维度检索"的事。

  • 需要在 Analyzer 里打开就点行右键 / 复盘按钮，跟 SCENE 3 的"在 Analyzer 打开"是同一个通道。

回到你的 3 个问题

  1. "5 个 mode 干嘛的"： 答案是它们错位了——5 个 mode 都是"事后"工具。v2 砍到 3 个 mode（采集 / 回放 / 历史），采集本身就是默认。
  2. "采集时需要数据流窗口"： SCENE 2 就是。Live strip + 大字号瞬时值 + 实时质量监控 — 主视图就是看流。
  3. "从 A2L 选好参数变量不就行了"： 是的。SCENE 1 左栏就是 A2L 树勾选 — 12 项一选完，立即出预估带宽和待录卡片，按 Record 就走。Preflight / Manifest 是录完以后的事，不进主流程。
