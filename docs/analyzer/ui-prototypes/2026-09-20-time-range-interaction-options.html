逻辑说明：为什么“全部”不应继续含糊地放在范围旁

先区分两个动作。“全时段绘图”重新获取当前 View 所选通道的全时段数据；“适配已绘数据”只移动图表视口。已经只绘制 12–24 s 时，后者不会凭空恢复 0–60 s。三种方案均将视口动作放回图表工具条。

当前源码。PersistentTop 允许取消勾选时编辑；时域绘图通过 range_enabled() 决定是否采用数值。_on_time_range_max_requested 在时域适配已绘数据，在分析页则清除指定范围并回到来源全时段，同一“全部”文案的效果不一致。

A 的自动采用仅针对用户输入。不是每次 valueChanged 都启用；恢复 View、切换来源、填充初始值、缩放或平移都不能伪造一次用户编辑。原型的“取当前视窗”是明确动作，只适用于横轴为时间的图；Custom-X 不能把通道数值当秒。原型有意让普通缩放不回写输入，以免覆盖手输草稿。

范围未通过校验时，阻止相应绘图。空值、非数字、开始 ≥ 结束、越界均给出就地提示，不悄悄回退全时段。C 中明确点击全时段绘图仍可执行，但保留并提示无效输入草稿。无数据时不用 0–0 s 伪装成可执行范围。

下一步边界。本页演示时域一个 View、一个具有连续 0–60 s 时间轴的来源。FFT/FRF/阶次等分析页当前具有来源范围和草稿确认机制；若采纳新设计，应另行明确每个分析 pane 的语义，不把时域设计直接覆盖过去。多来源按真实范围验证，不假定每条通道都覆盖整段时间。

原型不是实施。配色和密度贴近现有白底蓝色 Inspector；此页没有修改 PyQt 程序或项目状态。方案按钮、示例填入、绘图计数和“模拟无数据”属于试用工具，不是建议新增的产品工具栏。
