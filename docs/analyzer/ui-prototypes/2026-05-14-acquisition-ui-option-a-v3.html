这一屏吸收了你的 4 个问题

  • (Q1) 连接 ECU 是独立工序 — toolbar 下面的 健康 strip 是连接状态的真理来源（HW / CAN / XCP / DAQ / REC 五个 chip 配 LED）。任一变红，[采集] 按钮失效。CANape 里这块叫"connection status" — 我们让它一直可见而不是藏在菜单。
  • (Q1) Arm vs 立即开始 — Arm 进入触发等待（"踩油门到 3000 rpm 才开始录"，台架/路试常用）；立即开始 = 现在就写盘。两个并列，不是模式开关。
  • (Q2) 搜索 + 过滤 — 左栏顶部搜索框 + 6 个 chip：只看已选 / 有 DAQ / 最近 / 收藏 / 组 / 类型。2158 个 measurement 在这套过滤下回收得到 184 个、再到 12 个。
  • (Q3) Raster 怎么设 — 每个信号行有 @ 10ms ▾ 这种 pill，点开是下拉，列出 A2L 声明的 events；不可用的灰显，当前的高亮。这就是 ECU 端的"raster 规则"——通过 A2L 直接展示给用户。
  • (Q3) 批量 raster — 选多个信号时左栏顶出现蓝色 batch bar（图中是"3 已选"），下拉只显示全部选中信号都支持的 events 交集，不全支持会提示"X 个信号将跳过"。
  • (Q4) 卡顿规避 — 右栏的 录制预检 是核心：CAN 负载 / DAQ slot / 磁盘 / 采样事件——任一红线就 disable [采集] 按钮 + 给具体建议。这就是 CANape 没有的"预检阻断"——它让你配出会卡的组合，我们直接拦。
  • (Q4) 三线程 + 水位透明 — 状态栏里"ring buf 0%"就是 ring buffer 水位（录制时它会动），写盘走 64 KB 批写。本质上把 CANape 内部不透明的部分摆出来给用户看。

v3 一共吸收了 7 个设计决定

  1. 合并 Scene 1+2 为单屏 + 4 态机 — 主区永远 live，"采集"按钮 = 开始写盘，不是开始 stream
  2. 连接 ECU 是独立工序 — 健康 strip 5 灯做状态真理来源，未连接时主按钮变 [连接 ECU]
  3. 搜索 + 6 个过滤 chip — 应对 A2L 2000+ measurement
  4. 每个信号显示 A2L 声明的 events，可切换；不可用的灰显
  5. 多选 → 批量改 raster，下拉只显示选中信号的事件交集
  6. 右栏录制预检 — CAN 负载 / DAQ slot / 磁盘 / 采样事件 4 项，任一红就 disable [采集]
  7. 录制中右栏切到实时质量监控 — ring buffer 水位是健康度的真理来源，超 70% 自动降帧而非崩
