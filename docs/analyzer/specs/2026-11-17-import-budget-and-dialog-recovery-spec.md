# MF4 资源恢复与紧凑导入对话框 Spec

日期：2026-11-17。状态：**合同仍有效**。依据：[当前 Review](../reviews/2026-11-17-import-budget-and-dialog-regression-review.md)。执行：[Plan](../plans/2026-11-17-import-budget-and-dialog-recovery-plan.md)。结果：[执行报告](../reviews/2026-11-17-import-budget-and-dialog-recovery-report.md)。调查源码 `c126fcae`，用户版本 8.4.8。

## 1. 决策、范围和完成标准

三条工作线共享一个实施与集成负责人：

1. 内容型提示按内容定高，工作窗保留防退化保护，关闭图3回归。
2. 导入使用自有布局的轻量进度组件，真实阶段/进度由已有 coordinator 提供，关闭图2的语义与对齐缺口。
3. 资源失败保留结构化事实、支持显式重新检查与重试；MF4 的内存根因按既有原生采样方案解决，不能把错误框变好看当成图1已解决。

本 Spec 对[9月对话框 Spec](2026-09-05-cross-platform-dialog-layout-spec.md)只补充窗口用途区分和本次导入界面；不启动其余消息框批量迁移。资源策略扩展以此为合同；完整数据模型仍以[MF4 原生采样 Spec](2026-11-17-mf4-native-sampling-spec.md)为准，避免再建一套存储、分析或项目迁移方案。

完成分层：U=短提示与进度/错误体验；R=目标资源条件下 MF4 安全导入。U 可独立验收，但整个用户问题必须 U+R 都通过。R 以真实文件、正确数据、正式 broker、GUI 注册和 Windows 包实测为准。仍被预算拒绝时只能报 R 未完成，不能将“程序没崩溃”写成成功。

不包括全局换主题、字体/Qt 升级、直接提高默认预算、无条件强制打开、静默丢通道/降采样、全仓库窗口重写、修改源 MF4。开发探针与反事实 patch 不是生产方案。

## 2. S-G：几何按窗口用途约束

`ui_kit/dialog_geometry.py` 仍是唯一几何 owner。采用显式、向后兼容的用途/约束参数（名称实现时定），不按 windowTitle、objectName 文案或是否恰巧是 QDialog 猜用途。

- 内容型窗口：首选与 minimum 来自实际正文、图标、动作。允许正常 380×134 等短窗口；不存在通用的 200 高度 floor。
- Batch/UltraView 工作窗：保留已验证的内容 minimum、有效工作区检测、初次/显示后恢复与独立工具窗行为。已有调用默认仍保守，逐个把经核对的内容型 owner 接入新用途，避免批量改变其他窗口。
- 无边框/弹层/内嵌区域：保持原坐标系与预算合同，不套工作窗 floor。
- 首次 `apply_plan`、显示后 `_shrink_unaccounted_frame`、重排与 frame 修正必须使用同一个用途合同。不能只绕开一处判断，然后被另一处重新顶到 200。
- 拒绝工作窗计划时，记录拒绝原因并采用既有可用 fallback；内容型窗口不能以保留旧默认尺寸作为成功布局。`apply_plan` 的兼容返回合同保留，调用者不能把 False 无差别当作已完成尺寸应用。

短提示使用已有布局常量：普通左右24、上18、下20、图标48、图标正文间16、正文动作间16、按钮32基线。对于无详情/checkbox的一行提示：

```text
目标高度 = 上边距 + max(实际正文换行高度, 图标高度)
           + 正文动作间隔 + 实际按钮行高度 + 下边距
```

禁止固定整体高度、删除滚动区或用巨大 stretch 留出空面板。正常 12px 基线应接近134逻辑像素；跨平台按实测字体计算，不硬编码134。支持工作区内，最终高度相对公式的多余量≤8逻辑像素；正文区不因 Qt 自然 sizeHint 膨胀到221。长正文/详情才滚动，操作栏保持在滚动区外。

初次 show、字体变化、详情开合、屏幕变化后收敛；主文案与按钮完整显示，Enter/保存失败、取消/Esc/标题栏关闭行为不变。普通短提示与新进度框移除无对应功能的标题栏问号，仅作用于本次自有组件。

## 3. S-P：导入进度真实且对齐

拟新增 `ui_kit/import_progress_dialog.py`，使用 QDialog + layout + QLabel/QProgressBar/按钮；不依赖 QProgressDialog 内部手工几何，不新增全局主题或任务管理器。组件只显示 snapshot/发出取消意图；文件/session/结果归 coordinator 与现有 workflow。

布局：标题/当前文件 → 阶段与耗时 → 进度轨道 → 底部取消动作。普通客户区首选宽420、软上限560，工作区不足时缩窄换行，内容按需定高。普通水平边距24、上下18/20、行距8、操作区前16；取消按钮沿用32高/最小外宽74，长文案实测增长。标题、阶段和轨道使用同一个内容宽度，取消按钮最右端与轨道右端误差≤1逻辑像素。轨道完整横跨内容区；动画 chunk 的位置不作为轨道宽度。

文件名可中间省略，tooltip/可复制详情保留完整路径；不让长路径把窗撑出工作区。正文默认纯文本。耗时由现有任务开始时间/单一可回收定时器更新，不每个控件独立轮询。普通打开、恢复、Batch DBC、Replay 复用显示组件，分别保留原 coordinator 归属。

状态合同：

| 状态 | 显示/动作 | 数据合同 |
| --- | --- | --- |
| 等待/启动 | 当前第 i 个/共 n 个，阶段、耗时；busy | 文件序号不是完成百分比 |
| 读取但无计数 | busy、具体阶段 | 不编进度、不估剩余秒数 |
| 当前阶段有可靠计数 | 显示“当前阶段 xx%”，同步 bar | 不把阶段比例称为整文件进度 |
| 交接/注册/恢复 | 阶段切换，无可靠分母则回 busy | broker 1.0 不代表工作区提交成功 |
| 成功 | 已提交的文件计数/完成终态，确定进度可到100% | 仅在已有事务成功及目标仍有效后 |
| 部分成功/失败 | 明确已加载/失败数量、失败详情入口 | 不显示整体导入成功或成功100% |
| 取消中 | 即时显示“正在取消…”，禁用重复取消 | 等监督回收；不以隐藏窗口代替回收 |
| 已取消 | 已取消，可关闭 | 不触发成功回调；先前已成功文件按原合同保留 |

状态终态只发一次，不为展示100%增加阻塞 sleep。快速任务可以直接关闭并通过既有成功反馈确认，不要求强行保持一个满条。标题栏关闭与Esc等价取消，不能只关闭窗口让读取无声继续。程序成功关闭不得反向 cancel 当前或下个任务。超时/错误选择期间停止 busy 动画或显示等待用户处理，避免同一任务一边报错一边看似仍在读取。

同一 request 的阶段与比例同时供弹窗和底部状态栏消费，不再写两套独立判断。保留已有 request/session/target 校验、2秒协作宽限、线程回收和关闭等待；不引入GUI主线程 wait/join/processEvents 循环。

## 4. S-E：资源错误可解释、可复制、可重新检查

扩展现有 `ImportResourceError` 与 broker 错误 envelope，拟保留：resource_kind、unit、requested、limit、phase、estimate_basis、可选分项；兼容旧 message/detail。白名单类型、非负数、大小限制与协议兼容必须测试。字段缺失显示“未提供估算”，不能从本地化字符串推断数字；不能把所有 resource_limit 当内存错误。

资源种类至少区分内存预估、worker实际内存监测、输出传输量、临时磁盘、通道/文件数量。数量不显示MiB；磁盘不足给出对应提示；未知分类保留原说明及日志定位。请求和上限是同一维度才比较。使用现有 bounded JSON 协议，禁止任意对象或pickle。

内存预估拒绝的普通文案示例：

> 本次未导入此文件。预计导入资源需求约609 MiB，当前预算约476 MiB。
> 可关闭不需要的来源或其他占用内存的程序，再重新检查。重新检查后仍可能无法导入。

正文不堆 `MDF shared-axis conversion/alignment/frame`。详情保留精确字节、估算分项、源文件身份、request、阶段和日志定位；不声称已经分配609 MiB，也不把差值当作必须释放的内存。复制只进入本机剪贴板，不自动上传。

动作：关闭、查看/收起详情、复制诊断；内存预估拒绝额外提供“重新检查并重试”。优先复用修复后的 AppMessageDialog，详情折叠状态为本窗口展示状态，不写项目。新动作有稳定 action_id，不能通过中文按钮文本判断业务。

重试合同：旧worker已回收→重新核对源快照与原目标→重新取得可用内存/default_limits→新request ID/worker执行。仍不足立即以新事实拒绝，不在父进程解析，不自动提高memory/output上限，不无限重试。用户更换了项目/目标消失则原重试失效；多文件请求仅重试当前失败文件，不重复注册已成功文件。关闭不自动重试；超时的“延长并重试”继续只改变时间预算。

这提供恢复通路，但不能保证低内存机器立即成功。本期不提供“仍然强制导入”；未来若增加用户预算覆盖，须另有父子同时峰值与系统余量证据及明确合同，不能临时加一个无限制按钮。

## 5. S-R：解决内存根因及 MF4 打开验收

短期保留现有 admission；先建立资源分项/生命周期/同时峰值观测，只有确定不共存或确实消除的副本才能减少预算。`ImportBudget.used_bytes` 当前是单调累计估算，不能不改变数据路径就当作可随意 release 的活对象账本。

完整方案复用原生采样 Spec §3–9 与 Plan M0–M6：原生数组、共享轴、受控转换、typed transport、按需准备分析输入，避免 `Nmax × 所有通道` 公共表；不改采样点换内存。native 仍超预算时准确拒绝，不承诺任意大小MF4都能打开。

R验收必须包括：

- 当前历史事故样本：在固定 memory=498,988,944、output≤249,494,472 字节预算下走正式产品路径完成，不禁用数组安全检查、不改源hash、不丢支持范围内样本；计费与实际阶段峰值分别记录。
- 对此前样本的原生支持范围，以原生 Spec 的逐点/质量/物理身份 oracle 为准；52信号只是旧公共轴结果，不是native应保留的上限。
- 图2文件若可获得，单独记录hash/组/采样规模并复测；未获得标UNKNOWN，不能复用前一文件的结果。
- 低于必需资源的请求在分配前明确失败，失败后另一个正常文件仍可打开；取消、磁盘不足、源变化、项目/目标变化无半注册或迟到成功。
- Windows Full/Lite 的真实内存条件另测，固定预算回归不模拟Windows的RSS；原生工程值、项目迁移、分析、导出、Replay完成前不切产品默认。

上述目标在旧公共轴路径上未达到时，不能通过修改预期或提高测试预算宣布R关闭。若真实必需峰值证明固定预算不可达，报告needs revision并给出实测缺口，不伪造支持承诺。
