# 文件打开延迟与 WWT 首帧稳定性 Spec

2026-11-19 · 已实施，Windows 指标待验收 · 源码基线 `630bf656` · [配套实施计划](../plans/2026-11-19-file-open-latency-and-wwt-canvas-plan.md)

## 1. 用户目标与测量终点

用户反馈 Windows EXE 打开 MF4 从近乎即时退化到数秒，WWT 接受 WinWert 排版后画面跳动。本次优化要缩短从选择文件到可以使用通道的时间，并让首次显示的曲线位置可靠。继续遵守[原生采样合同](2026-11-18-mf4-native-completion-spec.md)和[导入恢复合同](2026-11-17-import-budget-and-dialog-recovery-spec.md)。普通打开沿用用户当前的共享轴／多采样率选择，项目重开沿用项目保存的选择。

| 观察量 | 起止与判定 |
| --- | --- |
| 打开到可用 | 从确认选中文件或拖放被接受开始，到目标 View 已按现有选择完成登记／挂载、通道可选、绘图操作可执行。测试用预定通道实际绘图验证可用性。 |
| 打开到首图 | 同一起点，到目标曲线、坐标轴及刻度首次自然绘制到前台。普通 MF4 由探针在可用时发出绘图动作；WWT 走自动排版。另记人工确认等待，自动接受时记为零。 |
| 进度反馈 | 记录状态栏开始、对话框出现／关闭与以上两个时间点。后台读取完成、进度条消失和首图可见分别计时。 |

## 2. 已有证据与边界

以下均来自两个真实 MF4 和真实 WWT 的 macOS 源码版探针。Windows EXE 上数秒延迟是用户观察，各阶段的占比待测。当前 Windows 使用文件夹式打包，每次读取用隐藏参数启动同一 EXE，入口提前分流到读取进程。Lite Modular 还会在扩展初始化中核验核心与所选组件的文件，普通 Full/Lite 的 bundled 分支走另一条路径。

| 样本／路径 | 已测结果 | 设计含义 |
| --- | --- | --- |
| 3.9 MiB、12 MiB MF4，共享轴 | 后者展开为 471652 行 × 53 列，表约 190.7 MiB。记录边界和共享轴预算约 0.9 ms，交接写出／读回约 178／114 ms。前者完整读取三次中位数 560 ms。 | 保留边界检查和预算，优化固定启动与大结果搬运。 |
| 同一 12 MiB MF4，共享轴预热 A/B | 三轮中位数 717 → 515 ms，终点是数据返回。预热在点击前已完成。 | 一次性预热值得实现；冷开、空闲内存和预热未完成时须单测。 |
| 同一 12 MiB MF4，原生多采样率 | 84 条轴，约 24.7 MiB 的交接目录含 1183 个文件。父端重建时分段扫描约 0.66 s。仅替换两端的严格递增快速判定，三轮中位数 1911 → 775 ms，样本的全部分段及 store revision 一致。 | 优先处理逐点循环，并减少小文件数。不同实验的时间不相加。 |
| 两个小 WWT | 热解析约 3 ms，完整读取约 219–221 ms。 | 短任务的弹窗可见性与真实读取成本分别优化。 |
| WWT 前台绘图 | U-Can 的画布外框固定，前两帧绘图区左界由 54.8 移到 43.3 逻辑像素。NLTNP 的无变化刷新使两轴从 −10…10、0…460 变为 −10.5…12、0…600。临时对照消除了两种偏移。 | 分别修复轴宽晚确定与普通刷新重新定轴，逐帧验收。 |

本地诊断可由计划中的样本和步骤重做。本轮原始记录在工作区 `.state/open-speed-analysis/` 的 `mf4_stages.log`、`native_ab.log`、`shared_warm_ab.log`、`bench.log`、`axes.log` 和 `compare.log`。这些日志用于追溯；产品和 CI 均无需读取它们。

## 3. 导入合同

**I1　每份文件保有独立的失败边界。** 保留受监督的子进程、Windows Job、源文件快照、请求身份、超时、取消、内存与输出预算、结果完整性及原子注册。解析器异常退出时主程序存活，原 View 和已有文件可用，下一次普通导入可成功。保留已验证的数组读取器和工程值精度。历史事故及原始文件的独立字节校验见[鲁棒性验收记录](../verify/2026-11-17-import-robustness-implementation.md)。

**I2　把可预先完成的初始化移出点击路径。** 普通桌面打开可在首个可交互帧之后准备一个一次性读取进程。候命期只初始化依赖，无文件路径、业务数据或请求预算。就绪进程仅接一个兼容请求，用完退出。请求到达时原子领取，每次尝试最多启动一次解析，用户确认的重试使用新进程；无可用进程时立即走现有按需路径。继续遵守现有解析并发上限，补位避开活动导入的内存峰值。候命进程有单一所有者、空闲回收和退出清理。不同包、运行时身份或扩展代次不能混用。Windows 先纳入 Job，再放行初始化。Lite Modular 使用既有文件核验和共享租约；测量空闲租约释放及关闭时的回收。Batch、项目恢复及非 MF4 请求可继续使用原 broker，预热失败可观测，真实数据／资源错误仍按原语义返回。

**I3　原生时间轴分段结果逐项相同。** 在 `native_signal_store.build_segments` 对一维、全有限、严格递增的轴快速构造唯一连续段。建议分块比较相邻原 dtype 值，含跨块首尾，约束临时内存；整数不做差分或 float64 转换。空轴、单点、重复、重置、连续非有限、首尾非有限及支持的非连续视图保留原语义。两端可继续独立重建；快速路径和通用路径均保留记录顺序、段边界和标志。原生 raw／physical／validity、只读性、共享轴身份及复合通道键逐项等价。

**I4　一次交接，减少读写遍数和文件数。** 先将写入与摘要计算合并，接收端对同一份字节完成验证和构造，对磁盘和内存先准入再分配，整批验证通过后才发布。针对 MF4 的共享轴列和原生数组，优先比较“清单 + 少量连续数据块”和现有逐数组文件。块内声明偏移、长度、形状、dtype、字节序及布局，验证越界、非法重叠、重复引用、截断、错配和总预算。逻辑共享通过显式引用恢复。继续返回当前 API 承诺的数据所有权，任务临时目录删除后数组仍然有效。共享 transport 的 WWT record store 等其他结果有往返兼容门禁。交接只存在于当前请求，工程文件格式独立于此改动。

**I5　进度表达当前工作。** 提交后立即更新状态栏。提议给短任务约 250 ms 的弹框延迟，超时仍在进行才显示；快速成功无迟到弹窗。耗时任务保留取消入口，等待用户选择排版／重试时及时展示对应交互。阶段文字按实际步骤区分读取、结果交接和绘图；确认排版时标为等待选择，取消、异常、关闭及下一请求均不得收到旧计时器回调。成功仍以导入事务提交为准。

## 4. WWT 首帧与刷新合同

**V1　首次可见时坐标轴布局已经稳定。** 通过普通时域 View 的恢复事务，在最终 X/Y、刻度和字体确定后，预量 overlay 的主左轴、第一右轴和额外右轴，再提交内部 PlotItem 布局。按最终设备字体和缩放测量。保留自适应宽度，长数字和单位可完整显示。继续沿用一次 `settle_view_restore()`、既有 Pin 提交和自然绘制确认。多窗口 WWT 一次插入保留的 View，绘制活动 View；其余 View 首次访问再绘制。

**V2　同一数据、可见性和视口的刷新保留 XY 范围。** 普通刷新保持每个关联轴的实际上下限。仅重投影刻度时不得触发“漂亮刻度”重设范围。Home、显式自动缩放、真正的曲线／滤波伴线可见性变更和拓扑改变仍依其现有策略定轴。实施时同时检查选择增量成功后的伴线定轴和普通 plot 尾部的刻度密度设置。采用通用时域行为，WWT 只提供初始 View 意图。

## 5. 验收与判定

- **Windows 实机性能。** 使用用户反馈对应的包型和样本（可取得时），加上 3.9／12 MiB 固定样本。同机对照优化前后及可取得的历史秒开包。分别测首窗刚可交互即开、候命已就绪后打开、连续打开多个文件。记录包型、构建号、采样模式、样本哈希、磁盘位置和文件缓存条件；重复打开同一文件与打开不同文件分开。每格至少 5 次，报告中位数、最慢值、单次明细、GUI 最长无响应间隔和父／子内存。优化前包按同样空闲时长对照。
- **提议的性能目标。** 对固定样本，Windows 就绪后共享轴打开到可用的中位数目标 ≤1 s；历史包能正确读同一数据时，同时以历史中位数 +200 ms 为体验目标。冷开和首窗可交互时间分别跟踪，候选中位数相对当前包的恶化容差取 10% 与 100 ms 中较大者。12 MiB 原生模式就绪后目标较当前同模式中位数降低至少 30%。交接收集读写字节、文件数、分段耗时与同时内存峰值。上述数字是设计目标；未达记录实际差距，缺 Windows 证据标 UNKNOWN。旧版崩溃的样本仅比较现版安全基线，不能拿失败耗时当历史成绩。
- **前台视觉。** 同一尺寸与 DPI，逐帧比较首次含有效曲线的自然 paint 和稳定帧。绘图区左右边界位移各 ≤1 逻辑像素，连续两次无操作重绘后 XY 范围等于首次稳定范围（允许浮点舍入），曲线、刻度、网格对齐。围绕一次已有图可见时的第二文件打开，检查无空白中间帧。Cocoa 和目标 Windows EXE 独立记录，offscreen 只证明行为。
- **完整性。** 同一样本验证两种采样模式各自的数值、身份及下游绘图；覆盖坏文件、预算拒绝、超时、取消、重试、关闭／项目切换、临时目录清理与随后的成功请求。通过阶段性能指标且满足数据与生命周期合同方可接收相应改动。
