# 自定义表达式检查：UI 与逻辑提案

日期：2026-10-21。状态：轻量版已获用户确认并已实现。取消结果卡片与独立检查行，采用小按钮、输入框颜色和点击提示。HTML 保留为交互参考。

原型：[表达式检查](../ui-prototypes/2026-10-21-expression-check.html)。它使用当前 Python 求值器对合成数据生成的固定结果演示交互，不执行任意用户输入，也不读真实文件。

## 目标与范围

在创建派生通道前，让用户明确知道公式能否执行、源数据是否满足要求、结果有多少无效点。检查通过仅表示当前输入及数据版本满足执行与数值检查，不能证明工程公式、量纲、系数或预期含义正确。

本次建议覆盖现有自定义表达式，不扩展表达式语言、不自动修公式、不新增重采样、不扩展跨文件运算。检查范围固定为当前编辑文件的整条信号，与当前图表选区、缩放无关。与创建使用完全一致的源与时间轴。

## UI 布局

保留原有表单顺序，仅在表达式输入框与 `?` 之间增加 28 × 28 px 小按钮。初始图标为 `✓`，提示为「检查表达式」。不新增结果卡片、详情列表、状态行或确认勾选。

```text
表达式  [ sqrt(A^2 + B^2) * 0.5 ] [✓] ?
A=通道A · B=通道B · t=时间 · ^ 为幂
名称    [ 留空自动生成                 ]
        [ ＋ 创建通道 ]
```

- 点击按钮执行检查，完成后输入框显示绿色或红色边框和极浅底色；同一按钮显示绿色 `✓` 或红色 `!`，提供颜色以外的提示。
- 完成后在按钮下方出现小浮动提示：标题与一两句原因。浮层不挤动表单，不是常驻面板；点外部、焦点离开该行、Esc 或再次点击按钮关闭。
- 已有有效检查结果时，点击按钮切换显示提示，不重复全量试算；修改公式/源/文件立即恢复默认边框、清除旧提示，下一次点击重新检查。仅改名称保留结果。
- 检查中按钮显示省略号并暂时禁用；允许编辑，旧请求结果不得覆盖新输入。中断或尚未真正求值时保持默认边框，不能误标绿色或红色。
- 通过提示示例：「检查通过。全量 1,001 / 1,001 点有效。」失败示例：「检查未通过。缺少右括号，请在末尾补上 )。」
- 空输入、语法错误、未知变量、源数据不匹配、结果有无效点均显示红色；标量和同源但合法的结果仍显示绿色，在提示中说明其含义。

视觉沿用白底、浅灰蓝边框、蓝色主操作、7 px 输入圆角、系统中文字体与等宽表达式。绿色 `#248653`，红色 `#ca414b`。浮动提示宽度不超过当前视口，可换行。保留原有帮助入口；HTML 中仅演示简短帮助。

## 检查与创建的关系

Check 是独立检查，不注册通道。创建时若尚未检查或结果失效，调用同一检查入口；无需为了创建手动先点 Check。

本轮 UI 简化不额外改变现有创建的数据容错：语法/数据错误、空数据及全无效仍阻止创建；部分无效用红色提示「10 / 1,001 点无效，首个在 3.00 s。仍可创建，曲线在无效点处断开」，继续保留现有部分 NaN 可创建的行为，不增加确认勾选。红色表示本次检查发现问题，不一概等于无法计算。若后续要求所有无效点都阻止创建，应作为单独的数据策略变更评审。

## 统一检查流程

1. **静态公式检查**：沿用归一化和 AST 白名单，检查空输入、语法、未知变量、函数白名单、可支持的参数规则、复杂度和指数限制。`referenced_names()` 只是引用提取，不能独自代表静态验证通过。完整规则应与求值器共享，不能在 UI 用另一套正则或 `eval` 近似实现。
2. **输入检查**：使用当前 `fid` 与通道实际身份解析已加载/本次新增源，按真实引用获取 A/B；未引用的 B 不阻断。t/time 使用文件时间轴。验证数值转换、1D、非空、长度及与现有时间轴的数据对应关系；缺失时间元数据按现有数据契约报错，不虚构采样率、不截断补齐。
3. **全量试算**：用正式创建的同一入口对整个信号执行。`mean/std/rms/median/cumsum` 等依赖全局或顺序语义，不能用抽样或任意切块代替。输入非有限点与结果非有限点分别统计，不能笼统把已有缺失数据说成公式除零。
4. **结果诊断**：维度、输出长度、有限点数/比例、首个无效样点及真实时间、有效部分的最小/最大值。空数组不调用无定义的 min/max；全无效没有数值摘要。常量/标量提供说明，合法零值不报错。
5. **分级与发布**：内部保留静态/数据错误、部分无效、全无效的区别；UI 通过为绿，发现问题为红，创建权限按上一节现有契约处理。只发布仍属于当前请求的结果。工程意图及单位推导不作为本轮自动判定。

目前 `evaluate()` 会把 Inf 统一变成 NaN。因此第一版输出宜写「无效点（NaN/Inf）」，不能伪称已区分除零、溢出和定义域错误。若需要精确原因，必须在原求值过程归一化前采集诊断，保留原返回兼容性；未经节点级证据不得断言某个子表达式是根因。原型中除零文案来自已知合成案例，不代表现有求值器有归因能力。

错误位置也要保真：例如 `^` 到 `**`、`π` 到 `pi` 会改变偏移。将归一化后的 AST 位置映射回原文后才可选中字符；没有可靠位置则只给行内错误说明。原始错误供日志保留，产品文案用中文说明原因。

## 所有权、并发与复用

- 纯数值检查与结构化结果放在 `signal/` 中表达式的拥有模块或同层小模块，不引入 Qt。沿用现有 `evaluate` 导出，不在 UI 复制求值算法。
- 对话框拥有检查状态、选中源、提示和创建动作；若引入 worker，Qt 侧单一协调者持有请求编号与生命周期。线程只读稳定的数值输入，GUI 线程负责取源快照与发布 UI。
- 请求身份至少含当前文件身份/数据修订、所用通道身份/修订、原始公式、时间轴版本及求值规则版本。不能用显示名称或数组长度替代版本。当前是否有可复用数据修订号需实现前核实；没有时用会话 generation 与受控失效，不能臆造已有 API。
- 输入编辑、源切换、文件切换、源删除/重建、操作切换、关闭/重新绑定对话框都使旧请求失效；改输出名称不失效。未用到的 B 切换可保守失效，但检查本身仍不能因为 B 无效而拒绝 A-only 公式。
- worker 返回时必须匹配当前请求身份；过期成功/失败均丢弃，不能覆盖新输入状态或继续待执行创建。关闭时停止发布，避免回调已销毁 Qt 对象。检查中编辑取消创建意图。
- 不做每次键入的全量计算。按钮触发检查；修改仅使结果失效。大信号用单个受控后台请求，合并待执行请求，旧任务即便无法立即停止也不得堆积并发计算。NumPy 原子运算的取消可先定义为结果废弃，文案不要承诺即时停止。
- 完整试算成本应显式承担；不能为了流畅把抽样成功显示成全量通过。资源不足或中断为未完成，可重试。异步框架的具体选择待量测真实大文件后确定。
- 同一未变更快照可短期保留已试算数组，在点击创建且满足创建条件时注册，避免立即重复计算；只保留最近一次，失效/关闭释放。若复用安全性无法证明，则重新检查。缓存存在本身绝不授权创建。
