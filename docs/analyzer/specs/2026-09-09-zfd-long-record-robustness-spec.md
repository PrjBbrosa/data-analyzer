# ZFD 长记录完整性与时基解析 Spec

日期：2026-09-09
状态：设计合同已形成，尚未实现。用户本次仅授权编写文档。
配套：[执行 Plan](../plans/2026-09-09-zfd-long-record-robustness-plan.md)

## 1. 问题与目标

用户报告：今天打开一个约一小时的 ZFD，程序只显示几秒，原文件暂时找不到。
已确认当前解析器存在独立可复现的点数截断缺陷；尚不能认定该缺陷就是遗失文件的唯一原因。

目标：受支持的 ZFD 必须完整读取声明的采样点，按文件内已验证的时间轴显示；无法完整解释的数据必须明确失败，不能静默返回短记录，也不能自动制造一个看似可信的秒数。

## 3. 范围与阶段

### A：确定缺陷修复

修正 32 位有符号点数解析、声明长度和文件边界校验，建立长记录回归。保持现有返回结构、公开入口及短样本数值兼容。A 可以单独验证，但不能宣称整个鲁棒性合同完成。

### B：受支持格式的结构化读取与明确失败

替换全文件 marker 搜索为按文件头、声明通道数、记录类型、完整长度顺序读取。取消固定偏移猜 dt 和自动 1 kHz 回退。

本轮完整支持的 profile：ZFGE2，首条且唯一的 type 0 等间隔时间记录，后续 type 4 float32 测量记录，全部引用第 0 条时间记录，点数一致。单位限定 `sec`、`s`（去首尾空白后不区分大小写）；这些别名明确映射到秒。

本轮不新增：type 1/2/3、多个时间记录、非零 X 引用、非时间 X 轴、其他时间单位转换、非 ZFGE2、损坏文件抢救、用户手动指定 Fs 对话框、导出、DSP 改动、版本发布。遇到这些 profile 外情况明确“不支持”，禁止沿用旧扫描器继续猜测。后续支持必须另有格式证据与合同。

## 4. 二进制与完整性合同

1. 根据本地原厂脚本读取 11 行文本头、文本注释数量及各条注释、通道总数，再逐记录读取。所有固定宽度和换行字段必须检查实际可读长度；EOF 必须立即终止，不得死循环。
2. 普通记录为小端 `int16 type + int32 count`，type 0 的额外保留字节按原厂脚本处理。注释/通道数字段按参考脚本宽度和符号读取；负值不解释为巨大正数。不得把所有 count 都改为无符号整数。
3. type 4 的名字、单位、X 引用、保留字节、两个 float64 显示范围和 float32 数据按顺序读取。显示范围只作 metadata，不能用于数据裁剪或时间推断。
4. 分配数组前验证 `count > 0`、`count * itemsize` 不超过剩余可读字节。先验证所有记录边界与支持范围，再构造返回组；任何声明记录损坏均整文件失败，不提交前几个完整通道。
5. 正好读完声明的 count，不能向下取整、截成低位、按剩余文件长度补点、用 `min(len(x), len(y))` 修齐。最后一点及尾部特征必须保留。
6. 测量数据区不搜索 marker。名字不要求符合 `A2: ...`；有标准 marker 前缀则提取为展示元数据，无前缀则保留完整名字。身份按物理记录序号保留，不用名字定位记录。
7. 声明测量记录后的字节不扫描成新通道。记录 `trailing_bytes`，视为未解释的非测量尾区；“完整”仅指声明测量记录与时间轴完整，不宣称尾区语义或全文件校验和已验证。
8. 不以固定采样点上限把大文件截短。继续使用当前读取方式即可，不要求 mmap/流式重构；检测长度在分配前完成。内存失败沿现有基础设施错误路径可观察地报告，不能返回部分结果。

## 5. 时间轴与数值合同

| 项目 | 规则 |
| --- | --- |
| 时间来源 | 必须来自已解析的 type 0；保存文件原始单位、起点和间隔 |
| 时间数组 | `t0 + arange(count, dtype=float64) * dt`；Time 列以秒计，不重置非零起点 |
| dt | 有限且 `dt > 0`；移除任意的 3,600 秒间隔上限。`dt=7200 s` 可是真实慢采样，不能回退 1 kHz |
| t0 | 本轮支持有限且非负起点；负起点明确为 profile 不支持，避免现有 GUI 范围控件悄悄夹到零。扩展负起点另需范围控件验收 |
| 数值可表示性 | 生成的时间值必须有限；多点轴必须严格递增；过大 t0 导致相邻时间相同也报错 |
| 对齐 | 每个测量通道 count 必须与唯一时间记录一致，X 引用必须为 0；不按 count 另分组并套用首通道 dt |
| 空/短 | count ≤ 0 拒绝；一点记录允许加载，跨度为 0，Fs 从声明 dt 传递，不能落入 FileData 的默认 1 kHz；分析是否可运行由现有短数据规则决定 |
| 测量数组 | 1D float64，原始 little-endian float32 解码；NaN/Inf 保留，不丢点、不改长；非有限时间轴拒绝 |
| Fs | 从已验证 dt 推导，包括一点记录；GUI 与 adapter 同一事实。不得通过会重建并丢失 t0 的 FileData 参数路径传入 Fs |

时基缺失、NaN、Inf、零、负值、未知单位必须失败。错误提示解释不能确定真实时长，建议核对源软件并重新导出。本轮不提供“仍按估算加载”。

## 6. 返回接口、身份与诊断

保持 `DataLoader.load_zfd(fp)` / `load_zfd_groups(fp)` 的 groups 接口；保留 `data`、`channels`、`units`、`channel_metadata`、`source_metadata`、`label_suffix`。B profile 成功时返回一组，suffix 为空。

保留原有 `source_kind`、版本、标题、文件名、重名诊断等字段。成功时 `fs_estimated=False`。新增源元数据置于 `source_metadata['zfd_import']`：

| 字段 | 含义 |
| --- | --- |
| `schema` | 本诊断结构版本 1，不是产品版本 |
| `parser_profile` | `zfge2-single-time-f32-v1` |
| `declared_record_count` / `parsed_record_count` | 含时间记录，成功时相等 |
| `sample_count` | 验证后的完整点数 |
| `time_record_index` | 0 |
| `time_start_s` / `time_step_s` / `time_end_s` / `duration_s` | 同一时间轴事实，duration 为末减首 |
| `measurement_records_complete` | 成功时 true，仅表示声明测量记录完整 |
| `trailing_bytes` | 声明记录后的未解释字节数 |

原始 type 0 名字、单位存入该字典的 `time_name` / `time_unit_original`。通道元数据补 `record_index`、`record_type`、`declared_count`、`decoded_count`、`x_record_index`，保留现有 marker、单位及显示范围字段。
同名消歧保持已有 `[marker_id]` 文案和 `renamed_channels`；无 marker 或重复 marker 用记录序号稳定消歧。`Time` 保留为时间列，同名测量通道必须消歧，不能覆盖时间。

`FileData` 对此已验证 ZFD 元数据消费 Fs 必须是窄适配，不改变其他格式的时间推断。若需要抽出构造 helper，应放 IO owner，GUI/adapter 共用，不能复制两份逻辑。
当前 adapter 的 ZFD group identity 为 count/dt。本轮单时间轴 profile 不扩展 group identity，不更改 source ID、项目 schema；将来多时间轴才讨论 t0/时间记录身份迁移。

## 7. 错误与产品反馈

格式/数据错误使用 `ValueError` 或其专用子类，至少携带文件名、记录序号（若已知）、字节偏移、原因；长度错误附声明点数及期望/可用字节。用户摘要使用中文，避免只抛 struct 异常。

示例：“ZFD 数据不完整：第 3 个记录声明 3,608,000 点，数据区不足，未导入此文件。”
时基错误：“ZFD 时间轴无效，无法确定真实时长；请在源软件核对并重新导出。”
不支持：“暂不支持此 ZFD 的多个时间轴，未导入此文件。”

GUI：复用现有加载失败路径；无新增成功源、无“已加载”成功提示，原来打开的源保持不变。禁止添加新 MainWindow 状态簇。成功加载的范围必须到达真实末点，用户能查看完整时长。
Batch：probe/load 共用 loader，错误进入现有单项失败/诊断路径，其他合法文件继续；不产生该失败项的分析结果，不另写进度/结果记录路径。
同步 `ui/hints.py` 和 `ui/quickref.py` 的 ZFD 支持范围/失败说明，保持短提示宽度合同；需要详细说明时使用 quickref。保留通用 `format_fs_estimated_notice` 兼容函数，不把本轮变成其他格式清理。
历史 release notes/spec 不改写成当前行为；只更新当前帮助中仍宣称自动 1 kHz 回退的说明。

## 9. 完成边界

实现完成要求 A1–A12 全部有对应结果；未运行 Cocoa 时只能报告“代码及 focused 验证完成，前台验收未完成”。原用户文件缺失单列为“现场同因确认 UNKNOWN”，不阻塞确定缺陷修复，也不能被合成文件替代为原文件验收。
Windows frozen 包验证仅在后续发布时执行，本轮不声明完成。多时间轴/type 1–3 的明确拒绝是本轮支持边界，并非已实现兼容。
