# 启动面板与软件底部提示面板：视觉反馈记录

日期：2026-09-23。状态：已纳入[晴空蓝白与启动交接实施计划](../plans/2026-09-23-sky-glass-panels-and-startup-handover-plan.md)，待执行；本记录不代表已修复。

## 用户要求与范围

后续计划必须同时覆盖 **启动面板** 和 **软件内的底部提示面板**。当前只记录反馈，不修改产品代码。

1. **文字渲染不统一。** 用户反馈粗体和非粗体都有问题。启动面板截图中，中文的字形、笔画粗细有不协调的观感，同一句正文也有粗细混杂；不能仅通过取消标题加粗解决。后续应统一中英文的字体选择、回退和字重策略，保证普通正文与强调文字都清晰、稳定；允许有意设计的标题/正文字重层级。
2. **面板底部仍有明显灰色投影。** 截图底边、右下角外侧可见厚重、叠层式灰色阴影。后续应消除这类底部灰边/拖影观感，与轻盈的面板材质一致。透明磨砂与外部投影是两个独立问题，加入磨砂不代表此问题已解决。
3. **两个面板一起优化。** 用户已明确软件内底部提示面板指点击底栏「?」打开的操作速查面板 QuickRefPanel，不是 Toast；目前所附截图只展示启动面板。不得把它仅理解为启动面板内部的 tip 区。
4. **配色已选定。** 用户选择「晴空蓝白」，HTML「玻璃不透明度」滑杆 65%（alpha 0.65）、磨砂 15px；整体与软件明亮蓝白色调协调，保留 B 的频谱图案与布局，不增加 slogan。
5. **启动交接新增要求。** 启动面板应在主窗口显示前或同时消失，不能主窗已出现仍遮挡。源码核查与本地真实 child 探针确认旧交接顺序和关闭投递缺陷，证据、修正方案与 Windows 原生验收要求见上述实施计划；尚未测量用户 Windows 包上的重叠时长。

## 后续 plan 必须包含的排查与验收项

- 分别追踪两个真实面板的字体设置、实际字体回退、字重、文字绘制方式，以及 Windows DPI/缩放路径。字体回退、合成粗体和缩放绘制仅为待排查方向，不能当作已确认根因。
- 分别确认系统窗口阴影、自绘阴影、Qt 图形效果、透明窗口边界是否参与底部投影；根因确认后在所属层修正，避免多个层重复叠加阴影。
- 以真实 Windows 面板为验收对象，覆盖普通/加粗中文、英文、数字与中英文混排，以及 100%、125%、150%、200% 缩放下的文字、圆角和底边。
- 检查浅色、彩色和深色背景下的文字可读性及底边外侧；磨砂开启与不支持磨砂时的回退显示都应检查。
- 两个面板分别提供修改前后截图。HTML 视觉参考与 offscreen 检查不能替代 Windows 原生验收；启动面板须保持及时出现、正常退出，底部提示面板须保持原有触发与关闭行为。
- 实施 plan 再根据查明的 owner 指定最小改动范围、针对性测试与原生视觉验证，不在本记录里预设架构重构。
