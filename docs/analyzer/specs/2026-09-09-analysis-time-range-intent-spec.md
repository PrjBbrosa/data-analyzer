# 分析时间范围：来源跟随、手动草稿与提示 Spec

日期：2026-09-09
状态：设计合同，尚未实现；本次仅文档。
配套：[执行 Plan](../plans/2026-09-09-analysis-time-range-intent-plan.md)

## 1. 目标与范围

加载或切换参与分析的信号后，默认时间框显示该信号可用的完整物理时间轴。只有明确的用户范围编辑才形成待启用草稿；程序初始化、绘图、缩放和恢复不得制造“用户选择了局部范围”的提示。

适用于单次 FFT、时频、阶次、FRF 的分析时间。分析画布的 X/Y 相机范围、时频切片游标、色阶不是计算范围。
本轮不修改 Batch、DSP 裁剪/插值/对齐算法、原始文件时间轴、产品版本；不新增通用框选工具。不重新设计时域页面现有的视口回写语义，但必须隔离它对分析页面的影响。

## 3. 产品规则与状态机

一个分析窗格的有效状态为：

- **full**：`pane.time_range=None`，无手动草稿；取消勾选，显示当前来源全范围。
- **draft**：`pane.time_range=None`，有用户提交且不同于全范围的草稿；取消勾选，显示草稿，轻量文字“范围已调整，尚未启用”。
- **enabled**：`pane.time_range=(lo, hi)`；已勾选，直接按该范围计算。
- **invalid/unavailable**：来源缺失、范围无效或已启用范围不适用于新来源；保持可解释的错误状态，禁止静默当作 full 计算。

| 事件 | 状态与显示 | 是否确认 |
| --- | --- | --- |
| 初次加入信号，full 下来源变更 | 更新全范围；无待启用草稿 | 否 |
| 初始化、重绘、自动适配、普通缩放/平移、Home、切片游标 | 不改分析时间状态与时间框 | 否 |
| 用户提交开始/结束编辑，未勾选 | 保存当前窗格草稿；若等同全范围则回 full | 计算时确认 |
| 用户编辑已启用范围 | 更新明确范围并按已有逻辑使计算结果过期，不自动执行 | 合法范围不确认 |
| 用户勾选 | 有草稿则应用草稿；否则使用当前全范围；先校验 | 不追加第二次确认 |
| 用户取消勾选 | 明确回 full，清除草稿，时间框显示全范围 | 否；不能立即重新询问刚取消的范围 |
| 分析页点击“全部” | 取消勾选、清除草稿、显示当前来源全范围；可复位时间预览 | 否 |
| 切到另一 View/窗格 | 投影目标窗格自身状态；不继承前一个时间框 | 否 |
| 同一窗格更换来源 | 未启用草稿丢弃并回 full；enabled 按 §6 校验保留 | 不在选源过程弹窗 |
| 项目恢复 | 仅恢复持久化的 enabled/full；无草稿 | 自动恢复不弹窗 |

“全部”的新语义仅在分析页改变；时域仍沿用其查看全图行为。两处文案须按模式说明，不能共用一个含糊 tooltip。
普通缩放包括 FFT 下方时间预览的 pan/zoom；分析页不得再自动从该视口认领计算窗口。现有明确“取时域范围”等命令保留直接启用语义，必须使用取值时的物理时间快照，而非任意画布 X 数值。将来新增框选范围工具另行设计，本轮不把普通框选缩放当作范围选择。

## 4. 全时段事实与来源身份

权威是当前计算目标窗格绑定的逻辑来源/通道，不是导航器里最长的文件，也不是旧缓存图的可见范围。

| 方法 | full 的展示与计算语义 |
| --- | --- |
| FFT / 时频单信号 | 所选 `(fid, channel)` 的真实时间轴首末值；不强制从零开始，不使用热图时间窗中心的起止时刻 |
| FFT 多信号叠加 | 显示各目标物理范围的外包络，并注明“各信号使用自身全时段”；保留逐信号范围，不把外包络空隙造为数据 |
| 阶次 | 信号物理范围为默认展示；手动 RPM 不额外约束。通道 RPM 的覆盖/对齐由现有 `_order_rpm_for` / `_align_rpm_to_signal_axis` 检查，不新增“取交集即可计算”的算法 |
| FRF | 当前 input/output 的共同物理范围；必须保留同逻辑来源、同 Fs、逐点对齐等既有规则；区间重叠只是范围事实，不等于配对有效 |

可用范围读取复用已有取信号时间轴路径，避免复制 DSP 准备。读取范围不能启动分析、触发重建原始时间轴或为了刷新两个框分配完整分析结果。FRF 可复用/抽取 `_frf_prepare_pair_samples` 的未裁剪来源事实，但不能让已启用窗口先裁剪后又充当 full。

来源身份包含方法、View id、窗格 index 和带角色的复合通道键；Order 包含 RPM 模式及通道，FRF 包含输入/输出方向。列表重排但集合和角色相同不应误清草稿；改变角色、替换文件、修改该源时间轴时必须失效。运行期可用源对象/时间轴版本核验，不能用短文件名/显示名作身份。

缺失/空时间轴：显示不可用状态、禁用计算，不能显示上一个信号的时间。单点允许展示同一首末值，但是否可计算由现有短数据规则决定；不把无效区间归一化为 None 后按 full 放行。
多信号中部分来源缺失要明确标出，不能悄悄排除后把其余范围宣称为全部目标。

## 5. 状态所有权与持久化

- `PaneState.time_range` 继续是唯一已启用计算范围；`None` 保持全时段兼容。
- 新增一个由 `AnalysisContext` 持有的运行期范围控制器（拟 `analysis_time_range.py::AnalysisTimeRangeController`），保存按 `(section, view_id, pane_index)` 索引的草稿、绑定签名和需要复核的来源变更。通过现有上下文协调，禁止在多个 MainWindow mixin 上增加散落的 mutable flags。
- 草稿含 `range`、`source_signature`、`origin=user_edit`；明确范围命令直接启用，不能伪装为用户输入框事件。full bounds 为派生事实，不能作为第二份持久化计算范围。
- 共享 `PersistentTop` 只投影当前窗格。程序 `set_range_values`/设置范围上限/恢复使用静默路径；单独的用户编辑提交信号交给控制器。不要用通用 `valueChanged` 或“值与全段不同”当作手动证据。
- 输入框失焦与计算按钮点击的顺序必须确保最新编辑先提交再预检；无改动的 editingFinished 不生成草稿；无效文本须报告错误，不静默回滚到旧数值继续计算。
- 草稿不进 QSettings、`.tlproj`、preset 或 Batch；无需 schema bump。切换窗格可保留本会话草稿；关闭/删除 View、移除对应 pane、关闭文件、清项目、teardown 清理相关记录。复制 View 复制已有 enabled 意图，不复制未启用草稿。
- 项目旧值 `time_range=None` 一律解释为 full，不从恢复的时间框或旧 xlim 反推草稿。已有合法 tuple 保留；损坏 tuple 必须可观察地报出，不能声称是用户选择全时段。

## 6. 来源变更与范围有效性

full：重新解析本窗格范围并投影。draft：源签名改变即清除草稿并显示新源 full；换回旧源不复活已清草稿。

enabled：保存原范围意图，不为适配新信号偷偷 clamp。若所有计算目标的物理范围都覆盖请求窗口，保留；若部分/全部越界，进入需复核状态并显示原因，计算前询问“使用新来源全时段 / 返回调整 / 取消”。选择全时段才清除 enabled，返回调整/取消不发计算、不丢用户原值。
对于不同长度的叠加信号，用户显式选择使用共同时间窗口时逐来源报告覆盖；不能静默漏掉无样本的目标。来源本身的对齐/采样错误仍走现有 preflight，不提供“全时段”绕过。

比较 full 与草稿时只容忍显示量化误差：当前时间框 3 位小数，端点容差取 0.0005 秒加浮点数值误差，不能再用全跨度的 1%（一小时会吞掉约 36 秒的真实选择）。物理时间轴保留原精度；full 状态计算传 None，不把显示舍入值作为裁剪参数。
手动区间要求有限、lo < hi，并至少包含所需数据；UI 检查合法性，算法层仍保留自身最低样本数等验证。负物理时间通过同步控件上下限展示，不能固定下限零导致夹值。

## 7. 计算前提示与提交事务

仅用户点击计算时检查，条件为“本次目标中存在本来源签名对应的手动局部草稿”，而不是“时间框看起来短”。

文案：“你调整了时间范围为 10–20 秒，但尚未启用。此次计算使用哪个范围？”
按钮：用选定范围 / 用全时段 / 取消。默认焦点为取消，不把非破坏性的全时段标为 DestructiveRole 或红色危险操作。

- 用选定范围：校验草稿后一次性写 `pane.time_range`、勾选、清草稿，再捕获参数和构造任务。
- 用全时段：清草稿与对应 enabled 范围，显示当前 full，再构造任务；下次不会重复提示。
- 取消/关闭：保留草稿、来源、勾选、缓存和任务队列，不产生任何计算。

无效草稿（倒置、非有限或越界）不提供可直接启用的选项：禁用“用选定范围”，允许明确用全时段清除或取消后修改；不得通过归一化静默放行。

一次计算涉及多个窗格时，先冻结本次目标和源签名，对全部目标做范围预检。汇总一次提示并列明窗格/范围；选定或全时段操作只作用于提示中存在冲突的窗格，其余已有合法 enabled 意图不变。所有选择暂存，全部验证通过才统一提交和发任务；禁止先发第一个窗格任务再询问第二个。
提示期间若来源/活动目标发生改变，旧选择不提交；取消本次启动并要求重新点击计算。窗口恢复、后台自动重算不弹草稿提示；草稿不参与自动任务。恢复出无效 enabled 状态应显示原因且停止对应自动计算，不能默默回 full。

## 8. UI 与兼容约束

保留现有时间框、复选框、按钮视觉语言；只加待启用/无效状态的轻量说明，避免因说明出现而推动整个 Inspector 跳变。状态行预留布局空间或采用已有稳定高度的提示区；真实 Cocoa 验收。

同步 `ui/hints.py`、`ui/quickref.py` 和当前帮助相关说明：未勾选用全时段；手动改值是待启用草稿；分析页“全部”清局部；普通缩放仅查看。时域对应说明保持其现有合同，别批量替换历史文档。
既有 `set_range_from_span`、`range_values` 等公开入口保持兼容；调用者按明确意图迁移，不能在 shared widget 内以猜测当前页面决定业务状态。
