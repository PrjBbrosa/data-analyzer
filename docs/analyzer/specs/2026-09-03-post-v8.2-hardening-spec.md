## 0. 决策结论

1. **先解锁门禁，再谈功能修复。** A1（conftest 补丁被 `monkeypatch.undo()` 连带撤销
   导致模态挂死）使全量 `tests/ui` 不可完成；任何「验收通过」在它修掉之前都是
   UNVERIFIED。它是所有 Task 的前置。
2. **fixed-point 是自检不是拒绝理由。** Smart Layout 的求解候选不得依赖
   `current_rect`（B1）；二次求解只用于诊断，不一致时以 L2 为结果再验一次而不是整笔拒绝。
3. **脏态守卫按「可持久化用户意图」的完整集合判定。** 凡是 `save_project` 会写进
   `.tlproj` 的字段（含 remarks、xlim/ylims、光标显示设置以外的 View 级状态），在守卫
   digest 时也必须可见（C1）；解决方式是守卫前做**只读**焦点 View 快照，不写回、不触发
   重绘，保持「Cancel 零突变」。
4. **快捷键的平台语义以真机为准，registry 是唯一事实源。** macOS 的 View 循环必须是
   Control+Tab（Qt `Meta+Tab`），tooltip / quickref / hints 必须由 `command_registry`
   生成而不是手写副本（C2 / C5 / D4）；registry 里不存在实际绑定的条目（`RESET_VIEW=Home`）
   要么真绑要么删。
5. **每个交互状态机都要有「离开再进入」的显式重臂，rebuild 不算离开。** 色标 × 的
   actionable 状态只能由真实的 `HoverLeave` / `leaveEvent` 解除（D1）；pill 的避让
   位移在投影更新时保留（E2）。
6. **Qt 对象生命周期对称。** popup 由 Qt 自关时同样 `deleteLater()`（D2）；卡片锁若是
   用户意图就进 snapshot 与 undo，否则从 spec 删除（B5）。
7. **死链路要么删要么恢复护栏，不能「仅测试可达」地活着。** WWT→UltraView 原生布局
   链路（B2 / B4 / F6）按 §2 决策 A 处理。
8. **文档扇出与实现同一次提交。** 帮助页 changelog、四个分析指南、`user-guide.html`
   补 09-01 ~ 09-03 六项用户可见交互；`CLAUDE.md` 版本与棘轮数字、stage-8 runbook
   构建路径同步。

## 3. 各区合同

### 3.1 测试基础设施（A1 / A2 / A3）
- `tests/ui/conftest.py` 的 autouse 守卫补丁改用**独立的** `pytest.MonkeyPatch()` 实例
  （`with pytest.MonkeyPatch.context() as mp:`），不与测试函数共享 `monkeypatch`；
  `tests/ui` 内任何 `monkeypatch.undo()` 之后守卫补丁仍然生效。
- 增一条显性告警测试：在 `tests/ui/test_qsettings_isolation.py` 同级新增
  `test_dirty_guard_discard_patch_survives_monkeypatch_undo`，构造 `mw.show()` 后
  `monkeypatch.undo()` 再 `mw.close()`，要求 200 ms 内返回。
- `tests/test_wwt_inplace.py` / `test_wwt_export.py`：模板 fixture 在**仓库 checkout**
  （`assets/wwt/` 目录存在）中缺失文件时 `pytest.fail`，仅在明确的 wheel/site-packages
  安装场景才 skip。
- A3 属仓库卫生，由**用户**自行处理（9 个 tracked 资产的恢复、根目录 untracked 文件）。
  实施者不得提交、还原或忽略这些文件；根目录 `ssh-keygen*` 不在任何 Task 范围内。

### 3.2 UltraView Smart Layout（B1 / B3 / B4 / B5）
- `_span_candidates` 的候选集合是 `(aspect, metrics, density)` 的纯函数，`current_rect`
  只能进入排序 tie-break（movement 惩罚），不能新增或删除候选。
- `solve_smart_layout(_validate_fixed_point=True)`：L1 与 L2 不一致时，以 L2 为结果做
  第三次求解 L3；`L3 == L2` 则接受 L2 并在 diagnostics 记 `fixed_point_settled_in_2`；
  仍不一致才 `fixed_point_failure`。诊断计数进 `SmartLayoutResult`，不新增标量分。
- 合同矩阵：n ∈ {4..12} × per_row ∈ {2,3,4} × preset ∈ {standard, 其余两档} × aspect
  ∈ {16:9, 4:3, None}，**带 `current_rect`** 的手动路径全部 accepted；集成测试
  `test_manual_smart_layout_reaches_a_fixed_point` 必须先断言首击 `plan.accepted` 且
  `committed_updates()` 非空。
- B3：`hit_cap` 时保留已完成的最优 beam 结果为 `best`，diagnostics 记
  `search_budget_exhausted`；controller toast 按 diagnostics 精确区分「搜索预算耗尽，
  已用已完成候选」与「等大网格降级」。
- B4：随决策 A 一并删除；若选 A2，则 pending group 必须产出被 Smart Layout 消费的
  captured aspect，否则仍删。
- B5：按决策 B。
