# 四模块显式计算、缓存恢复与显示刷新统一规范

日期：2026-10-11。范围：FFT、FFT-vs-Time、Order、FRF。状态：已实施；验证范围见同日 verify 记录。

## 1. 问题与依据

修复前代码把 Inspector 草稿同时当作缓存查询请求和显示结果身份。`_reconcile_section_result_validity` / FRF reconcile 在编辑时自动发布命中的缓存；显示刷新则用草稿查缓存，造成已有图消失。`_rerender_analysis_section_from_cache` 调用 heatmap `do_*`，使 dB 管理窗口保存触发真正计算。项目恢复把所有有源 View 当成计算请求。2026-10-11 的 Cocoa 参数矩阵、真实 dB 保存按钮探针和 offscreen 项目往返已复现；原始记录位于 `.state/analysis-auto-refresh-20261011/`，这些是修复前证据。

本规范替代 2026-10-04 result-validity plan 中“编辑返回任一缓存即恢复当前结果”的规则，以及此前“打开项目自动计算所有有源 View”的规则；其他数值、源身份、对比与视口合同保留。

## 2. 用户规则

| 操作 | 是否计算 | 显示规则 |
| --- | --- | --- |
| 编辑窗函数、NFFT、重叠、加权、源、RPM、I/O 或计算时间范围；应用预设 | 否 | 保存草稿；保留上次结果并标记待计算。即使新草稿命中缓存，也不自动应用 |
| 点击计算 | 缓存命中则零 DSP；否则提交计算 | 唯一应用新请求的入口；成功后绑定该结果并清除待计算状态 |
| 调整 Linear/dB、参考值、坐标、色图、色阶、相位显示 | 否 | 只改变已应用结果的呈现，保留待计算状态；没有结果就保持空图 |
| 保存 dB 参考目录或切换 Auto/Manual | 否 | 同上，包含对话框和编辑器两条入口 |
| 切换 View、模块、对比焦点、关闭再打开对比 | 否 | 恢复该 View/pane 本次会话的已应用结果；不能凭公共缓存命中生成新图 |
| 打开项目（包括过去算过的项目） | 否 | 恢复源、参数、预设、布局和显示意图；计算结果不持久化，统一显示“点击计算” |
| 计算失败、取消、输入无效 | 否（不追加请求） | 保留上次成功结果及待计算状态，明确反馈错误；不能把旧结果标成新结果 |

FFT 下方的源信号时域预览可以随源/范围更新，它不是频域计算结果。编辑后再改回原值仍不重新发布缓存；再次点击计算可立即复用缓存。

## 3. 状态与身份

每个 pane 区分草稿、显式提交快照与已应用结果。草稿仍由 `AnalysisViewState.params` 和 `PaneState` 源/范围拥有。新增会话内 `result_binding`，记录已接受的请求快照及实际成功结果键；共享缓存仅存数值，不代表展示授权。请求快照冻结参数、复合源身份、范围、RPM/I/O 和修订号；结果绑定不包含数组副本、Qt 对象或进程外身份。

`PaneState.request_revision` 在计算意图变更，以及按各模块现有 busy/排队策略准入后开始一次新的显式计算尝试时递增。新尝试先将旧结果标为待计算，再冻结请求；因此预检失败或主动取消（即使服务不发失败回调）也不会把旧结果冒充成功的新结果。异步结果只有在 View、pane 身份和提交修订仍匹配时才能成为已应用结果；切走但未编辑的原 View 可以接收自己的完成结果，不可影响当前焦点。编辑后再改回不能使旧在途请求复活。结果可留在公共缓存，但过期完成不得替换绑定或清除旧绑定的 pin。

已应用键是缓存驻留 pin 的依据。删除 View/pane、清会话、重开项目要对称清理；复制 View 不隐式获得计算授权。缓存失效或源卸载后不得显示另一个请求的结果，显示待计算/源缺失状态。已应用请求的源标签、单位和 effective facts 跟随结果快照；不能用草稿源给旧结果贴标签。

FFT 多源请求允许部分成功：绑定只包含成功源和对应真实键；失败源明确反馈，不伪装全部成功。全部失败保留旧绑定。单信号兼容入口遵守同样规则。

## 4. 显示与交互

显示刷新读取已应用键和快照，叠加当前 View 的显示设置，不执行 `do_*`，不查草稿决定换图。缓存恢复、普通刷新、对比刷新共用这一身份规则。保留独立 View 参数、共享按键、右键路由、半色标签与旧结果上的标注/游标。显示更新不能清除“上次结果/待计算”事实卡状态。

无需改变 DSP 算法或项目 schema。运行时绑定不序列化，旧项目与新项目一致手动计算；保存的仍是用户编辑意图。用户帮助和 Inspector 提示必须说明项目重开需点击计算。

## 5. 验收

四模块逐一执行：空图编辑；显式算 P0；缓存预置 P1 后编辑到 P1；修改显示；切 View/对比并返回；再点击计算。断言 worker/同步 FFT 次数、实际结果身份、源标签和待计算标记。dB 对话框保存及 Auto/Manual 均须零计算；未计算与已计算项目保存重开均零计算。覆盖异步编辑/改回/切走/删除、失败、部分成功、缓存失效和 legacy single。

要求实际 Qt 控件信号和事件排空；offscreen、Cocoa 测试窗口、前台用户应用和 Windows 分别记录，不能互代。运行受影响 owner 测试、状态所有权/导入/信号连接边界及既有对比回归；本任务不是发布，不默认跑全库。
