日期：2026-09-05 · 修订：R1 · 状态：**文档就绪，产品实现进行中（T0–T4 代码；T5 被 G3/G4 拦住；跨平台验收未完成）**。

配套文件：[实施 Plan](../plans/2026-09-05-cross-platform-dialog-layout-implementation-plan.md) · [原因分析与完整静态入口清单](../reviews/code-reviews/2026-09-05-windows-dialog-layout-audit.md)。本文定义目标行为；审查报告中的源码和测量是历史基线，不表示当前工作区已经实现本文。

## 1. 目标、证据与范围

修复 Windows 下提示框外框紧凑、按钮占比失调，以及相同布局缺口导致的文字裁切、长内容撑窗、操作栏出屏和弹层越界。保持用户已接受的 macOS 留白、颜色语义与正常屏幕操作结构。

已知用户 Windows 显示缩放为 **100%**。现有程序已经启用 Fusion 和高 DPI；Qt 5 的消息框仍存在平台专属布局分支。当前最有证据的解释是平台布局与项目按钮 QSS 组合失衡；用户那份 Windows 包的实际 Qt、字体、屏幕工作区和异常截图尚未获取，不能把这个解释升级为已实机确认的唯一根因。

审查基线覆盖 77 处消息框、5 处输入框、20 处文件选择调用，另有自定义对话框和弹层。**调用数是盘点基线，不是 bug 数，也不是永久硬编码配额。** 已用生产控件与 QSS 在 macOS offscreen、DPR=1 下复现批量预览长警告、配置管理器最小尺寸、长文件名、长 tooltip、游标弹层底边越界和按钮字体变化裁切，详细数值见审查报告。

本轮产品范围：

| 类别 | 必须完成的结果 |
|---|---|
| 应用消息框 | 自有布局组件；分批迁移应用交互提示；每个旧入口都有迁移结果或有证据的例外 |
| 数据/表单对话框 | 有限工作区内正文可访问，底部确认/取消始终可达 |
| 锚点弹层与轻量提示 | 内容有界、先定尺寸再定位置，处理四角、长内容与锚点失效 |
| 已有防护的界面 | 增加边界回归，只修复失败的防护，不重做已接受的布局 |
| 输入框、文件选择、菜单与主窗口 | 纳入兼容验证；仅有可重复失败时做所属模块的最小修复 |

非目标：DSP/Auto-NFFT、图表渲染算法、项目格式/dirty 语义、Qt 主版本升级、全局换字体、调整系统缩放、强制 Win32 DPI awareness、重写系统文件选择器、全局清理 fixedSize。沿用已有 `control_style.py` 尺寸体系、全局样式加载入口及 diagnostics；不建立第二套 UI 主题。

## 3. 应用消息框组件

### 3.1 所有权与构造

新增 `mf4_analyzer/ui_kit/message_dialog.py`，承载 `AppMessageDialog` 及轻量创建/执行入口。使用 QDialog、QDialogButtonBox 和应用自有正文布局；不继承 QMessageBox 来修改其私有网格，不 monkeypatch Qt 全局类，不向 MainWindow 增加跨 mixin 可变状态。

组件只接收展示信息及动作描述，不接收项目/session 对象或执行保存、删除等业务回调。业务所有者获取明确结果后执行操作。同步与非阻塞展示复用同一控件及一次性结果提交路径。

组件输入至少包括：稳定 `prompt_id`、标题、主文案、可选补充文案/详情、图标级别、动作列表、默认动作、退出动作、模态方式、可选 checkbox 状态。每个动作明确 `action_id`、完整显示标签、语义角色，以及需要兼容时的标准按钮值。`action_id` 不由文案、列表序号或按钮屏幕位置生成。

结果至少包括：`action_id`（可为空）、可选标准按钮值、checkbox 状态、关闭原因（按钮/默认键/Escape/窗口关闭）。校验重复 action_id、引用不存在的默认/退出动作等编程错误，不默认为“同意”。未迁移的复杂接口不得伪装为全量兼容的 QMessageBox。

动作描述还需明确是否关闭窗口。Help/Apply 等非关闭动作通过 `action_triggered(action_id)` 通知所属界面，不提交终态；关闭动作通过唯一的 `completed(result)` 提交通道。组件本身不执行业务回调，也不能将这两个通知都接到同一个保存/删除函数。

### 3.2 正常布局与尺寸

下列数值是新组件在普通 12px 控件字体下的 **R1 逻辑像素设计值**，不是用户截图物理尺寸反推值，也不是旧控件实测值。它们只作用于新组件，不能全局覆盖其他 QDialog/QToolButton。

| 项目 | R1 规则 |
|---|---|
| 外侧留白 | 左右 24，上 18，下 20；紧凑工作区可减至 12，不减为零 |
| 图标 | 使用当前 style 的标准图标，48 为首选逻辑尺寸；按 DPR 提供清晰图像，几何不乘 DPR |
| 图标与正文 | 16 间距；正常情况下图标在左、正文在右 |
| 正文与动作区 | 16 间距；动作区正常位于正文列下方 |
| 首选客户区宽度 | 380；普通内容按测量在 380–560 内调整，都是软目标；工作区不足时可更小 |
| 动作高度 | 使用现有 `CONTROL_HEIGHTS['base']` 的 32px 基线；字体/多行需要更多高度时向上增长，同一排取最高值 |
| 短按钮宽度 | 最小外框 74；长标签按实际字体 + 水平 padding/border + 内容余量计算 |
| 动作 padding | 水平各 10，垂直各 4，1px 边框，文字内容宽预留 8；不得把内容最小宽误当外框宽 |
| 动作间隔/顺序 | QDialogButtonBox 的当前平台布局为准；不硬编码 Mac/Win 顺序，不抹掉平台的破坏性动作分组间隔 |
| 字体 | 沿用实际解析出的应用控件字体；主文案明确加粗，补充文案普通字重；不硬依赖 Mac 或 Windows 独有字体 |

32px 是选择现有普通控件轨道；旧 QMessageBox 短按钮离屏实测 30px 不作为新组件必须逐像素复制的合同。Cocoa 验收必须确认新提示整体仍保有用户认可的留白与比例。保留保存/警告橙色、丢弃/危险红色和取消中性样式的语义；复用当前消息框色值，不引入“warning”到通用 CONTROL_ROLES 的无关扩展。

横向动作无法容纳时，先使用允许的客户区宽度；仍不足则用 QDialogButtonBox 的纵向布局并让动作区跨越两列。不要假设 QDialogButtonBox 自动换行。单个完整标签仍超宽时使用组件局部的多行标签布局，按实测行高扩展按钮；完整 action_id 和 accessibleName 不变，不以只剩 tooltip 的省略按钮承载危险操作。宽度变化必须重新计算正文换行、动作排布和总高度，不允许在两个方向反复振荡。

QDialogButtonBox 提供平台顺序、角色和方向属性，但自动默认按钮不等于产品默认键；默认/退出必须由组件显式管理。[Qt 5 QDialogButtonBox](https://doc.qt.io/archives/qt-5.15/qdialogbuttonbox.html)

### 3.3 返回值和键盘行为

| 情景 | 强制结果 |
|---|---|
| 未保存项目点保存/Enter | 输出 `save`，原 dirty guard 执行保存；保存失败/另存为取消继续阻止离开 |
| 点不保存 | 输出 `discard`，只由原业务所有者决定继续离开 |
| 点取消/Escape/标题栏关闭/Alt+F4 | 未保存项目输出 `cancel`，不执行保存或丢弃 |
| 其他有危险动作的提示 | 保留既有显式安全默认；没有显式默认的入口须在迁移台账中记录实际行为和明确目标，禁止由首个 AcceptRole 猜测 |
| 标准 Yes/No/Cancel 等调用 | 兼容入口返回原标准按钮值；不得把 `QDialog.Accepted == 1` 当作 `QMessageBox.Yes`，也不能用 bool 抹掉 Cancel |
| 多个 RejectRole/NoRole | 调用者明确退出动作；无法证明原退出动作时先保留该入口待验证，不能猜测 |
| 单按钮通知 | 明确关闭映射；保留原调用方是否检查结果的行为 |
| Action/Help/Apply/Reset | 默认不关闭；按该入口冻结的行为执行，不能把任意 clicked 都连接到 accept |
| 默认动作被禁用 | Enter 不提交其他动作，不自动退到首个 AcceptRole；安全退出仍可用 |

复用 `set_unique_default_button()`，展示后也检查默认键唯一性；不注册全局 KeyPress filter。IME 预编辑和输入控件本身的编辑/确认优先；Space 激活当前按钮。现有 DbReference 单元格 Enter、UltraViewSheet Return 不关闭等例外保持。

`open()` 入口必须继续非阻塞，window-modal 不变为 application-modal。持有方保留存活引用，父窗口关闭时安全释放，关闭结果只提交一次；在 clicked 回调中销毁父窗口也不能二次发出结果。重复打开旧提示按原所有者策略替换/复用，不积累悬空窗口。用于测试的受支持导出/注入 seam 需保留；必要迁移应同步更新生产消费者与测试，不只让旧 mock 跳过新路径。

### 3.4 文案与长详情

普通数据文案明确以纯文本展示，避免路径/错误信息中的 `<...>` 被自动识别为富文本。确需受信富文本的入口必须显式声明并单独验收。用户提供的文件名、通道名不拼接为可执行动作或身份标识。

主文案与补充/详情进入可滚动正文；动作区不滚动。错误详情、警告和路径全文可选择/复制，展示折叠不丢原文。包含 `&` 的按钮文案需要区分 mnemonic 与字面符号，测量对象应是实际渲染标签，不是未经处理的原始字符串。

## 4. 统一屏幕预算与定位

### 4.1 支持边界

R1 以 **availableGeometry 逻辑工作区**定义布局边界，而非物理屏幕分辨率：

- 普通布局验收至少覆盖 800×600、960×540 和 1366×728。
- 新消息框、表单滚动壳和关键弹层的紧凑模式必须在 640×360 内保持必要操作可达。允许正文滚动、表格水平滚动、动作区纵排；不要求所有内容同时显示。
- 480×320 等更小工作区用于防崩溃/无误操作压力测试，不承诺完整桌面工作流。不得借此把超大 minimum 固定到屏幕外；不能容纳全部操作时，必须保留安全退出，不能自动选择破坏性动作。
- 12/16/24px 是新组件字体适配测试输入，不代表本任务新增全应用字号设置或承诺全应用自动跟随 Windows 文本辅助设置。

### 4.2 预算与计算顺序

`ui_kit/dialog_geometry.py` 是新增的共享几何所有者。公开输入包含可用工作区、锚点或父窗口矩形、窗口装饰边距、首选尺寸、内容约束与位置策略；输出客户区/外框目标矩形及是否需要紧凑/滚动布局。几何计算可注入矩形独立测试，Qt 取屏和应用几何保持薄层。

所有矩形统一为逻辑像素。设 `A` 为工作区，`M=8` 为普通屏边安全间距，`F` 为窗口框架边距：客户区预算为 `A` 扣除 `2M` 及 `F`。不对 QRect 再乘 DPR。正常验收要求 `frameRect ⊆ A.adjusted(M,M,-M,-M)`；无足够空间的异常预算缩减安全间距但不能得到负尺寸。

处理顺序必须为：

1. 按锚点全局中心选屏；普通对话框首次按 parent 的顶层窗口选屏，已显示可移动窗口按自己的当前屏幕；最后才 primary。内嵌 flyout 使用宿主局部 rect，不能套全局规则。
2. 提取可用工作区与客户区预算。显示前用可观测的框架估计；显示后排队校正实际 native frame。不能把固定预留 32/72 当作最终框架真值。
3. 调整正文换行、滚动范围、动作排列与布局最小尺寸；必要时释放旧 maximum/minimum 冲突，再重新测量。
4. 将首选尺寸限制在预算内。禁止用 `max(hard_minimum, screen_cap)` 重新突破预算。
5. 使用最终 frame 尺寸定位：弹层优先下方、其次上方，最后完整矩形 clamp；普通窗口按宿主合理居中后 clamp。负坐标、Qt right/bottom 包含边界的约定保持一致。

允许普通窗口被用户扩大到工作区内的任意尺寸；后续字体/工作区变化只纠正不再可用的几何，不反复恢复默认 380/1180 等宽度。不把屏幕尺寸约束持久化为项目分析状态。

### 4.3 更新与生命周期

首次 Show、字体/StyleChange、文案/详情变化、QWindow.screenChanged、当前 screen 的 availableGeometryChanged 均需触发所属窗口的一次合并布局。QLabel 文本变化由所有者明确通知，不假设 Qt 有通用 TextChange 事件。屏幕/DPR变化还需让图标使用当前屏幕的清晰资源。

重排调度归窗口所有者；持有 pending/reentrancy 标志，只有几何确实变化才 resize/move。静止输入在首次校正后必须收敛；排空队列后继续处理空闲事件不得再改变几何或持续重排。禁止轮询定时器与全应用 resize/键盘拦截。跨屏后断开旧屏幕信号，销毁时断开连接、清空引用并取消待执行工作；延迟回调使用有 Qt ownership 的对象，避免对已删除 wrapper 调用。

短期 Popup 可选择在宿主移动/滚动/关闭时关闭，下次打开重算；不能自动关闭仍在编辑 Fs 的 RebuildTimePopover，必须保留其现有失活与 accept-race 合同。普通工具窗保留可拖动、非模态和 transient-parent 行为。

| S14 | QInputDialog / QFileDialog / QMenu / QComboBox / 主窗口启动 | 保留原组件路径，纳入字体/小屏/多屏检查；只有确定失败才做对应所属模块修复，并记录处置证据 |
| S15 | 搜索图标、View 的 +/溢出等紧凑控件 | 作为不回归合同；不批量改 416 个尺寸调用或突破现有 QSS 特例 |

摘要只用于非交互轻量提示，不用于应用确认的风险文案、批量警告和错误详情。若某个 tooltip 承载唯一完整信息，必须先提供可访问全文的位置，不能先截断再声称已满足 C08。

## 6. 迁移与兼容

迁移台账使用 `module + owner symbol + semantic prompt_id` 标识，行号只用于导航。当前 77 处入口全部先进入台账，新增/移动调用重新归属。终态只允许：`migrated`（新组件且语义/视觉通过）、`retained_verified`（有明确理由、仍符合本范围合同）、`blocked_external`（说明缺少的外部证据）；pending/blocked 都不等于完成。

示范入口未通过 Cocoa 与 Windows 原生运行对照前，不大范围迁移其他 QMessageBox。共享几何和已复现 P1 的工作可独立推进。旧消息框字体测宽 helper 可在过渡期修复 polish 时序和重新布局，但不因此宣称平台比例问题已解决，也不能覆盖调用者已有完整 stylesheet。

同步提示先迁移；Cockpit 非阻塞提示单独一批。所有迁移保持旧业务封装方法的返回合同；组件采用自己的结果类型，标准按钮适配显式映射，不实现一个未经验证的 Qt API 替身。遇到真实测试注入兼容需求，保留或显式迁移该 seam 的全部消费者，不能新增生产逻辑来识别“是否处于测试中”。

无证据的“启动 fallback”不能作为批量豁免。目前 77 处是应用界面调用；只有实际执行时尚无完整 UI 依赖的入口，才可逐项登记低依赖例外。

## 7. DPI、字体、打包与诊断

保留 `app.py::_configure_high_dpi()`、Fusion 和单一 `load_stylesheet()` 路径。独立 Cockpit demo 的启动一致性单独检查；不要把已经复用 QApplication 的 Full 内 Cockpit 再初始化一次。既有 Windows 文字清晰度计划不构成本任务调整全局 hinting/字号/rounding policy 的授权。

新增 `ui_kit/layout_diagnostics.py` 只收集 UI 事实，通过既有 `diagnostics.py` logger 输出；后者保持 import-safe，不在模块顶层引入 ui/Qt。默认只记录低频环境信息；详细逐控件布局通过显式诊断模式开启，不收集完整业务路径/用户数据。字段至少包含 Qt/PyQt、平台插件、底层 style、有效字体/字号、屏幕 DPR/逻辑 DPI/工作区、客户区/frame、按钮实际文字需求与几何、prompt_id、相关 QT 覆盖变量和 QSS 版本/校验标识。按显示/状态变化合并，禁止 resize 日志风暴。

提供冻结包可用的诊断入口，不依赖 `.state` 脚本或 QtTest。版本、构建工具版本和 QSS 校验在构建阶段记录到产物元数据；Full/Lite 从同一受控 UI 依赖环境生成。若没有已验证的 Windows 版本组合，先记录为待验，不凭 Mac Qt 版本随意锁定 Windows。PE manifest/兼容性覆盖先测量再决定是否需要修改。
